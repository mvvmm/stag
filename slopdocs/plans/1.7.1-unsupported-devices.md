# 1.7.1 Unsupported devices: Implementation Plan

> Status: **done (2026-10-02)**, pending playtest of the Preview on a real phone. Parent: [implementation-plan.md](../implementation-plan.md) step 1.7.1. Extends the Unsupported screen from [0.2](0.2-game-shell.md).

## Goal

The game is desktop only, keyboard + mouse. Today the only gate is WebGPU, and current phones and tablets (iOS 26 Safari, Android Chrome) have it, so they load a game they can't play. This quick fix turns them away with a clear screen instead.

When it's done, the Unsupported screen shows when any of these is true:

- **No mouse or trackpad** (new): the screen says it's desktop only and offers "Continue anyway".
- **No WebGPU** (exists): `navigator.gpu` is missing or `WebGPUEngine.IsSupportedAsync` is false.
- **The engine fails to start** (exists): `startShell` throws, and the screen shows the error detail.

Out of scope: touch controls, a mobile layout of the game, small-window checks, analytics on who gets blocked.

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Device detection | **No fine pointer:** `matchMedia("(any-pointer: fine)")` is false | Feature-based, no user-agent sniffing. Blocks phones and touch-only tablets. An iPad with a trackpad or a touchscreen laptop still gets in, because *any* pointer counts. |
| Other reasons | **Kept as they are:** no WebGPU, startup failure | They become reasons of the same screen. |
| Message | **One screen, text per reason** | `device`: "Desktop only" (needs a keyboard and mouse). `webgpu`: "WebGPU required" (today's text). `error`: "Couldn't start" plus the error detail. |
| Override | **"Continue anyway" on `device` only** | For a misdetected device or a tablet with a Bluetooth mouse. It isn't remembered, so the screen asks again on every visit. The WebGPU and error screens stay hard blocks, because the game can't run there. |

### Defaults I picked (object if you disagree)

- **The device check runs first.** It's synchronous and cheap, and a phone without WebGPU is better served by "Desktop only" than by "WebGPU required". "Continue anyway" then runs the WebGPU check as usual, so it can still land on the WebGPU screen.
- **The detection lives in `src/ui/device.ts`** as `deviceSupported(): boolean`, next to the screen (not `unsupported.ts`: on macOS's case-insensitive disk it clashes with `Unsupported.tsx`). It's one line, so it gets no test (it reads `matchMedia`, so it isn't pure logic).
- **`Unsupported` takes a `reason: "device" | "webgpu" | "error"`** (+ `detail`, + `onContinue` for `device`). It keeps the existing styling (CSS module, tokens). "Continue anyway" is a quiet text button under the body, not a primary call to action.
- **Dev preview: `?unsupported=device|webgpu|error`** replaces `?nowebgpu` (dev builds only, ignored in production, like before). `error` shows a fake detail string. AGENTS.md and `devlog/README.md` are updated. Old devlog entries keep mentioning `?nowebgpu`, since they describe their time.
- **`implementation-plan.md` tech decisions** already say "Desktop only, keyboard + mouse"; the Platform row gains "(other devices get the Unsupported screen)".

## Steps

1. **Branch** `1.7.1-unsupported-devices` off `main`. Bump `cf` to the latest beta (AGENTS.md).
2. **Detection:** `src/ui/device.ts` with `deviceSupported()`.
3. **Screen:** `Unsupported` takes `reason`/`detail`/`onContinue`; text per reason; the "Continue anyway" button (opts into `pointer-events`, already on `.screen`).
4. **Bootstrap:** in `main.tsx`, split `bootstrap()` into the device gate and `start()` (WebGPU check, `startShell`, the rest as today). `device` renders the screen with `onContinue` → `start()`. Replace `?nowebgpu` with `?unsupported=`.
5. **Docs:** AGENTS.md (dev-only flag, `main.tsx` description), `devlog/README.md`, link + tick this step in `implementation-plan.md`.
6. **Check:** `pnpm check`, then the acceptance list below, in dev and on the Preview.
7. **Devlog** `devlog/1.7.1-unsupported-devices/index.md`: what and why, screenshots of the three screens (desktop width) and of `device` at phone size (agent-browser with a mobile viewport / touch emulation). Add it to the index.
8. **PR**, checks and Preview green, report the Preview URL. The user merges.

## Acceptance criteria

- [x] A phone (real device or agent-browser touch emulation without a fine pointer) shows "Desktop only" instead of the game. *Emulated; a real phone on the Preview is the user's playtest.*
- [x] "Continue anyway" starts the game normally on that device (or shows the WebGPU screen if WebGPU is missing).
- [x] A desktop browser with a mouse goes straight to the game, no flash of the screen.
- [ ] A touchscreen laptop with a trackpad goes straight to the game. *Not tested on hardware; `any-pointer: fine` is true there by definition.*
- [x] `?unsupported=device|webgpu|error` shows each screen in dev and is ignored in the production build.
- [x] The screen fits a phone viewport (no horizontal scroll, readable text, tappable button).
- [x] `pnpm check` is green.

## Notes

- **Emulating a phone in agent-browser.** `set device "iPhone 16 Pro"` only sets the viewport and user agent: headless Chromium still reports a fine pointer, so the gate doesn't fire. What works is launching Chrome for Testing with `--blink-settings=primaryPointerType=2,availablePointerTypes=2,primaryHoverType=1,availableHoverTypes=1` (2 = coarse, 1 = none) and attaching with `agent-browser --cdp <port>`. Passing that flag through `--args` / `AGENT_BROWSER_ARGS` doesn't work, because agent-browser splits it on its commas.
