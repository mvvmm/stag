# 0.1 Project Scaffold: Implementation Plan

> Status: **done (2026-09-27).** Parent: [implementation-plan.md](../implementation-plan.md) step 0.1.

## Goal

Set up a clean, strict TypeScript + Vite + Babylon.js project with lint/format, tests, the agreed directory layout and core dependencies. When it's done, `pnpm dev` shows a throwaway **smoke-test scene** that proves every core dependency works together. `pnpm check` must pass.

Out of scope, handled by later steps: the real engine bootstrap, resize handling and fixed-timestep loop (0.2), input (0.3), the Inspector and dev tools (0.4), Cloudflare/wrangler and the remote repo (0.5).

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Architecture | **ECS with [miniplex](https://github.com/hmans/miniplex)** | Entities are plain typed objects; systems query them. Babylon is a rendering layer that mirrors ECS state. |
| Lint / format | **Biome** | One tool, one `biome.json`. No ESLint or Prettier. |
| Screen UI | **Preact + @preact/signals** | JSX via `@preact/preset-vite`. Signals bridge game state to the HUD without per-frame re-renders. |
| Styling | **CSS Modules + `tokens.css`** | Design tokens as CSS custom properties; no Tailwind. |
| Tests | **Vitest, Node environment, logic-only, colocated `*.test.ts`** | Pure simulation code only; keep Babylon out of tests. |
| Cloudflare | **Deferred to 0.5** | Pure Vite static build for now. No wrangler and no `@cloudflare/vite-plugin` yet. |
| Git | **`git init` in 0.1, no hooks** | The scaffold is the first local commit. Remote/GitHub in 0.5. Quality gate = `pnpm check` (CI later). |
| Done criterion | **Smoke-test scene** | Babylon mesh + miniplex entity/system + Preact overlay + CSS module. It gets replaced in 0.2. |

### Defaults I picked (object if you disagree)

- **Babylon imports:** use `@babylonjs/core` (ES modules) and import from the package root for now. This avoids side-effect-import pitfalls. Switch to deep imports during the 9.6 performance pass if bundle size matters.
- **Versions:** latest stable of everything at implementation time. Pin Node 24 via `.nvmrc` + `engines`, and pnpm via `packageManager` (currently 10.26.0).
- **TS strictness:** `strict` plus `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`. Leave out `exactOptionalPropertyTypes`, which is too noisy with ECS partial entities.
- **Path alias:** `@/*` → `src/*` (in tsconfig and in the Vite/Vitest resolve config).
- **Formatting:** 2-space indent, line width 100, double quotes, trailing commas. Biome's recommended rules, with import organizing on.
- **Editor:** `.vscode/extensions.json` recommends the Biome extension; `.vscode/settings.json` sets Biome as the default formatter with format-on-save.
- **Solo:** add a `Dev` process (`pnpm dev`) to `solo.yml`.

## Dependencies

**Runtime:** `@babylonjs/core`, `miniplex`, `preact`, `@preact/signals`

**Dev:** `vite`, `typescript`, `@preact/preset-vite`, `@biomejs/biome`, `vitest`, `@types/node` (for config files)

Explicitly **not** added yet: `@babylonjs/inspector` (0.4), `@babylonjs/loaders` (1.6 / 9.1), `@babylonjs/havok` (maybe never), `wrangler` (0.5), and any UI kit.

### Architectural rules (go in AGENTS.md)

1. **Simulation is separate from rendering.** `ecs/` and `systems/` must not import from `@babylonjs/*` or `preact`. This keeps them unit-testable in Node and ready for the fixed-timestep loop in 0.2.
2. **Babylon mirrors the ECS.** `render/` creates and disposes meshes via miniplex query `onEntityAdded` / `onEntityRemoved` and copies transforms each frame.
3. **UI reads signals.** The game writes to signals at low frequency (e.g. health changes), and Preact components read them. The UI never reaches into the ECS directly.
4. **Tests sit next to the code** as `foo.test.ts`, and cover systems and pure helpers.

## Smoke-test scene (throwaway)

This proves every piece works together. It lives in `main.tsx` plus a couple of small files, and 0.2 removes it.

- `ecs/world.ts`: an `Entity` type with optional `transform` and `spin` components; `export const world = new World<Entity>()`.
- `systems/spin.ts`: `spinSystem(world, dt)` rotates every entity that has `transform` + `spin`.
- `systems/spin.test.ts`: a unit test showing the rotation advances by `speed * dt`. This proves Vitest, path aliases and the ECS work in Node.
- `render/`: a basic Babylon `Engine` + `Scene`, a dark clear color, a hemispheric light plus one directional light, and a box whose mesh is created when the entity is added and synced from `transform` in the render loop.
- `ui/`: a Preact `<SmokeLabel />`, styled via a CSS module that uses tokens, showing the text "Druid — scaffold OK" and a live FPS number from a signal updated about 4×/s.
- The canvas fills the viewport. The `#ui` overlay is absolutely positioned with `pointer-events: none` by default; interactive elements opt back in.

## Steps

1. `git init`; add `.gitignore` (node_modules, dist, coverage, .DS_Store, *.local, .wrangler).
2. Create `package.json` (`type: module`, `packageManager`, `engines.node`) and `.nvmrc`; install the deps listed above with pnpm.
3. Add `tsconfig.json` (bundler resolution, `jsx: react-jsx`, `jsxImportSource: preact`, strict flags, `@/*` alias, `types: ["vite/client"]`).
4. Add `vite.config.ts` (the Preact preset, the `@` alias, and a Vitest `test` block with the node environment and `src/**/*.test.ts`).
5. Add `biome.json`, formatting everything including JSON and CSS, and `.vscode/` settings.
6. Add `index.html`, `src/main.tsx`, `src/env.d.ts`, `ui/styles/tokens.css` and a global reset.
7. Implement the smoke-test scene (ECS world, spin system + test, Babylon render sync, Preact label).
8. Add scripts; run `pnpm check` and `pnpm build`, and fix anything that fails.
9. Update `AGENTS.md` (commands, layout, architectural rules, "use pnpm") and add the `Dev` process to `solo.yml`.
10. Tick 0.1 in `implementation-plan.md` and make the first commit: "Project scaffold (0.1)".

- [x] `pnpm build` produces `dist/`, and `pnpm preview` serves it working.

## Implementation notes

- Versions installed: Babylon 9.28, miniplex 2.0, Preact 10.29, @preact/signals 2.11, Vite 8.3, TypeScript 7.0 (native `tsc`; there's no JS `tsserver` in the package, so VS Code uses its own TS unless the native-preview extension is installed), Biome 2.5, Vitest 5.0.
- Biome 2.5 deprecates `rules.recommended` in favour of `rules.preset`. Note that `biome migrate` wrote `"preset": "none"`, which turns all lint rules off. The config uses `"preset": "recommended"` instead.
- The production bundle is about 6.7 MB (1.5 MB gzipped) because Babylon is imported from the package root, so Vite shows a chunk-size warning. That's expected; it's a job for the 9.6 performance pass (deep imports, code splitting).
- Verified in headless Chrome: dev and preview builds both render the spinning box and the Preact label.
