# 0.2 Game Shell: Implementation Plan

> Status: **done (2026-09-27).** Parent: [implementation-plan.md](../implementation-plan.md) step 0.2.

## Goal

Replace the 0.1 smoke test with the real game shell:

- a **WebGPU** Babylon engine bootstrap, with a clear screen for unsupported browsers
- resize and high-DPI handling
- a **fixed-timestep simulation loop** (60 Hz) that runs separately from rendering, which **interpolates** between ticks
- pause, time scale, and auto-pause when the tab is hidden

When it's done, `pnpm dev` shows a throwaway **loop test scene** that makes the loop's behaviour visible. `pnpm check` must pass.

Out of scope, handled by later steps: the real input layer and action mapping (0.3), Inspector/stats/tuning panel (0.4), the grey-box arena and real camera (1.1), hitstop (2.7), the pause menu (6.1), and single-tick stepping (0.4 if we want it).

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Tick rate | **60 Hz fixed** | One constant, `TICK_HZ`. Systems always get `dt` in seconds and never assume a tick count, so changing to 120 Hz later is a one-line change followed by a feel check. |
| Interpolation | **Yes** | Rendering runs at the display refresh rate (120/144 Hz is fine) and blends between the previous and current tick using the accumulator `alpha`. This costs up to 1 tick (~16 ms) of visual latency. |
| Backend | **WebGPU only** | `WebGPUEngine` + `await initAsync()`. No WebGL2 fallback. Unsupported browsers get a friendly screen, not a black canvas. Engine creation lives in one function, so adding a fallback later would be a contained change. |
| Demo scene | **Loop test scene** (throwaway) | Fast-moving boxes plus an overlay showing FPS, sim ticks/s, alpha and state, with keys for toggling interpolation, pausing and slow-mo. 1.1 replaces it. |
| Time control | **Pause + time scale** | `paused` and `timeScale` on the loop. `dt` stays fixed, and `timeScale` changes how many ticks run. Auto-pauses when the tab is hidden or the window loses focus. |
| Determinism | **Soft determinism rules** | Systems use only the fixed `dt`, all randomness comes from a seeded RNG passed in (never `Math.random`), and nothing in the sim reads wall-clock time. We don't promise bit-identical results across machines, and there's no input recording yet. |
| Resolution | **Device pixel ratio, capped at 2×** | A single `MAX_PIXEL_RATIO` constant, which becomes a graphics-quality setting later (9.6 / 16.1). |

### Defaults I picked (object if you disagree)

- **The loop core is pure and tested.** `core/loop.ts` knows nothing about Babylon or `requestAnimationFrame`. It takes a frame delta and calls `update(dt)` N times, then returns `alpha`. Babylon's `runRenderLoop` drives it with its own `performance.now()` delta, which lives in the shell, not the sim.
- **No spiral of death.** Frame delta is clamped to 0.25 s, and at most 5 ticks run per frame. If the cap is hit, the leftover accumulator is dropped (the game slows down instead of freezing).
- **Pausing** stops accumulating time and freezes `alpha`, so the rendered frame doesn't jump. User pause and auto-pause are separate flags, so returning focus doesn't unpause a game the player paused on purpose. On resume the accumulator starts fresh.
- **Interpolation state lives in the ECS** as a `prevTransform` component. A snapshot at the start of each tick copies `transform` → `prevTransform`. The renderer lerps position and rotation (Euler, shortest arc per axis). A `snapTransform(entity)` helper sets prev = current for teleports/spawns, so they don't smear across a frame. Entities without `prevTransform` render at their current state.
- **Simulation pipeline:** `systems/simulation.ts` exposes `createSimulation(world, rng)`, which returns `step(dt)`. `step` runs the snapshot followed by an ordered list of systems. Pure and unit-testable.
- **Seeded RNG:** `core/rng.ts` is a small, fast seedable PRNG (sfc32, seeded via splitmix32) with `next()`, `range(min, max)`, `int(min, max)` and `pick(array)`, plus tests. We add it now because the determinism rule depends on it, and the demo scene uses it.
- **Resize:** a `ResizeObserver` on the canvas calls `engine.resize()`. The hardware scaling level is set from `min(devicePixelRatio, MAX_PIXEL_RATIO)` and updated when the DPR changes (e.g. when the window moves between monitors).
- **Render rate:** uncapped, driven by rAF (the display refresh rate).
- **Unsupported screen:** a Preact component (CSS module + tokens) that explains WebGPU is required and lists supported browsers. It opts back into `pointer-events` so its link is clickable. It's shown when `navigator.gpu` is missing, `WebGPUEngine.IsSupportedAsync` is false, or `initAsync()` throws. A dev-only `?nowebgpu` query flag forces it, for testing.
- **Demo keys** use a throwaway raw `keydown` listener in the demo module (the real input layer is 0.3): `I` toggles interpolation, `P` pauses, and `T` cycles the time scale through 1 → 0.25 → 0.05.
- **Stats signals** (FPS, measured ticks/s, alpha, paused, time scale, interpolation on/off) are written about 4×/s, following the "UI reads signals" rule.

## Architecture

```
main.tsx
  └─ bootstrap(): check WebGPU → render <Unsupported/>, or start the shell
shell.ts (Babylon-aware wiring; the only place sim + render + loop meet)
  ├─ render/engine.ts      createEngine(canvas): Promise<WebGPUEngine>, DPR cap, resize
  ├─ render/scene.ts       scene, camera, lights (demo camera for now)
  ├─ render/meshSync.ts    ECS → mesh mirror with interpolation (alpha)
  ├─ core/loop.ts          fixed-step accumulator, pause, timeScale (pure)
  ├─ core/rng.ts           seeded PRNG (pure)
  ├─ systems/simulation.ts createSimulation(world, rng) → step(dt) (pure)
  └─ demo/loopTest.ts      spawns demo entities, demo keys (throwaway)
```

Frame flow (inside `engine.runRenderLoop`):

```
frameDelta = now - last            // wall clock, shell only
{ alpha } = loop.advance(frameDelta)  // runs simulation.step(1/60) 0..5 times
meshSync.sync(interpolate ? alpha : 1)
scene.render()
every ~250 ms: write stats signals
```

2. `core/loop.ts` + tests covering: the fixed tick count for a given delta, accumulator carry-over and `alpha`, the frame-delta clamp, the tick cap dropping the remainder, paused (no ticks, alpha frozen), timeScale (0.25× → a quarter of the ticks over time), and resume starting fresh.

## Implementation notes

- **Verified in headless Chrome** (real WebGPU adapter via `--headless=new --enable-unsafe-webgpu`, driven over the Chrome DevTools Protocol):
  - The production build runs at 60 fps and 60 ticks/s.
  - `T` gives 15 and 4 ticks/s at ×0.25 and ×0.05. `P` gives 0 ticks/s with `alpha` frozen. `I` toggles interpolation.
  - At a 2× device scale factor the canvas is 2560 px for 1280 CSS px. At 3× it's still 2560 (the cap works).
  - `?nowebgpu` shows the Unsupported screen in dev and is ignored in the production build.
- **Verified by the user** in Chrome and Firefox Developer Edition:
  - 120 fps and visibly smooth on a 120 Hz display.
  - Auto-pause on tab switch / window blur works.
- **Not yet verified:** Safari, and moving the window between Retina and non-Retina displays (the 2× cap itself was verified headless).
- **Cross-browser testing decision:** automated checks use headless Chrome only.
  - Headless Firefox couldn't be driven here: Developer Edition won't start with a custom profile, and stock Firefox fell back to software rendering and never opened its WebDriver BiDi port.
  - Safari has no headless mode.
  - Selenium or cloud grids wouldn't fix either problem, so Firefox and Safari stay manual checks.
- **Pixel ratio:** we set Babylon's hardware scaling level ourselves (`adaptToDeviceRatio: false`), because Babylon's own DPR-change handling in `resize()` ignores `limitDeviceRatio`. A re-armed `matchMedia("(resolution: …dppx)")` listener catches DPR changes, and a `ResizeObserver` on the canvas handles size changes.
- **Resuming** doesn't reset the accumulator. Instead the loop discards the first frame delta after a pause, so the rendered frame doesn't jump and no catch-up ticks run.
- **Babylon's `engine.getFps()`** returns `Infinity` when the frame delta is 0 (e.g. under headless virtual time), so the stats overlay guards against it.
- **The demo seed** is taken from wall-clock time in `main.tsx` and logged to the console. Seed display/replay comes in 8.5.
- **Also added** `core/math.ts` (`lerp`, `wrapAngle`, `lerpAngle`) with tests, used for shortest-arc rotation interpolation.
- **Auto-pause uses window blur**, so clicking into DevTools pauses the game. That's intended, but worth knowing while debugging.
