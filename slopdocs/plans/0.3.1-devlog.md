# 0.3.1 Devlog: Implementation Plan

> Status: **done (2026-09-27).** Parent: [implementation-plan.md](../implementation-plan.md) step 0.3.1.

## Goal

Start a **devlog**: a private record of how the game was built, so we can look back at the process later (and maybe turn it into blog posts). Each finished step gets an entry with:

- a short write-up of **what we built, the decisions we made and why** (including rejected alternatives)
- **screenshots** of the game at that step, taken automatically by the agent with [agent-browser](https://github.com/vercel-labs/agent-browser)
- optional **videos** you record with QuickTime, compressed automatically by a pre-commit hook

This step sets up the folder, the template, the tooling and the workflow rule. It also **backfills 0.1, 0.2 and 0.3**, using screenshots from their commits and write-ups drawn from the plans, the commits and our earlier Claude Code sessions.

Out of scope:

- publishing anything (a public blog/devlog page can come with the 16.4 marketing site)
- an in-game capture hotkey or canvas recorder
- running `pnpm check` in the pre-commit hook
- a scripted, repeatable shot list

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Purpose | **Private record for looking back** | Written for us, not for players. Raw material for blog posts later. |
| Location | **`devlog/` at the repo root** | Not in `slopdocs/`. Not in `public/`, so it never ships with the game. |
| Structure | **One entry per step** | `devlog/<step>-<slug>/index.md`, with the entry's media next to it. The slug matches the step's plan file (`0.3-input-layer`). |
| Write-up | **Short fixed template** | ~300–600 words: what we built, key decisions and why, surprises and problems, media. See [Entry template](#entry-template). |
| Media storage | **Plain git, with size limits** | No LFS. Screenshots are PNG. Videos are compressed H.264 MP4s of about 10 MB or less. Raw recordings are gitignored. |
| Screenshots | **Automated by the agent with agent-browser, ad hoc per step** | At the end of a step, the agent opens the build, sets up whatever shows off the step, and captures it. There's no scripted shot list to maintain. |
| Screenshot count | **Scales with the step** | Engine/system steps: 1–4 shots. Art, atmosphere and VFX steps (1.5, 9.x, biomes…): many, e.g. before/after pairs, several angles and lighting setups, close-ups. |
| agent-browser install | **Repo devDependency** | `pnpm add -D agent-browser`, pinned in the lockfile, run with `pnpm exec agent-browser`. |
| Videos | **Optional; you record them with QuickTime** | Record in Firefox fullscreen (or any browser) with QuickTime / Cmd+Shift+5, then drop the `.mov` into the entry folder. |
| Video compression | **`pnpm devlog:video`, run by a husky pre-commit hook** | It scans `devlog/` for any video that isn't compressed yet, compresses it, deletes the raw file and stages the result. The hook runs only this for now. |
| Backfill | **0.1, 0.2 and 0.3 get full entries** | Screenshots come from each step's commit, checked out in a temporary git worktree. Write-ups come from the plans, the commits and the earlier Claude Code session transcripts. |
| Workflow | **An entry is a required part of finishing a step** | The agent writes the entry and takes the screenshots, and they go into the step's commit. You can add a video afterwards (the hook compresses it in whatever commit it lands in). |

### Defaults I picked (object if you disagree)

- **Screenshot format:** PNG at a 1920×1080 viewport, device scale factor 1. Files are named `NN-what-it-shows.png` (`01-overview.png`, `02-moba-move-pin.png`) so they sort in reading order.
- **Screenshots run against a production build.** Use `pnpm build && pnpm preview --port 5747`, which is also what 0.3 was verified against. That keeps port 5746 free for your dev server. Debug overlays stay in the shot when they're part of what the step shows (e.g. the 0.3 input overlay).
- **Headless first, headed as a fallback.** 0.3 was verified in headless Chrome with a real WebGPU adapter, so agent-browser's headless Chromium should work. The first implementation step proves it. If WebGPU is unavailable headless, use `--headed` and/or the GPU flags, and write down what worked in `devlog/README.md`.
- **Video encoding:**
  - H.264 (`libx264`, CRF 26, preset `slow`), `yuv420p`, `+faststart`, scaled down to at most 1920 wide, at most 60 fps
  - audio dropped (QuickTime screen recordings have none unless the mic is on)
  - a poster frame `<name>.jpg`, taken at 1 s
  - if the result is over 10 MB, one retry at CRF 30, then a warning (the commit isn't blocked)
- **What counts as "uncompressed":**
  - any video file under `devlog/` that's not an `.mp4` (`.mov`, `.m4v`, `.mkv`, `.webm`, `.avi`)
  - any `.mp4` without the `comment=devlog-compressed` metadata tag that the script writes
  
  Checking the tag with `ffprobe` means compressed files are never re-encoded, and a big MP4 dropped in from elsewhere still gets handled.
- **Raw formats are gitignored** (`devlog/**/*.{mov,m4v,mkv,webm,avi}`), so a raw recording can never reach the index even when the hook is skipped.
- **Hook behavior:**
  - The hook scans the **working tree** (not just staged files), compresses, removes the raw file, and `git add`s the `.mp4` + `.jpg`.
  - With nothing to do, it exits in milliseconds and needs no ffmpeg.
  - If there's something to compress and `ffmpeg`/`ffprobe` is missing, it fails with an install hint (`brew install ffmpeg`).
- **The script is TypeScript run by Node 24 directly** (`node scripts/devlog-video.ts`, native type stripping), with no build step and no extra deps. It uses only the `node:` built-ins and shells out to `ffmpeg`/`ffprobe`/`git`. `scripts/` is a new top-level folder, and Biome and tsc cover it.
- **Sessions are sources, never committed.** The agent reads `~/.claude/projects/-Users-mvm-code-game/*.jsonl` to recover the interview Q&A, rejected options and course corrections. Only a summary goes into the entry. It contains no raw transcript excerpts, emails, home-dir paths or tool output dumps.
- **Index:** `devlog/README.md` explains how the devlog works (capture procedure, video workflow) and lists the entries in step order, one line each: step, title, date, link.
- **Dates** are the step commit's date. **Voice** is "we" for the project and plain, past tense.

## Screenshot procedure (goes into `devlog/README.md`)

1. `pnpm build && pnpm preview --port 5747` (in the background).
2. `pnpm exec agent-browser open http://localhost:5747`, then set the viewport to 1920×1080.
3. Wait for the scene to render (a short wait, or until the canvas has drawn at least one frame).
4. Put the game into the state worth showing, using clicks and key presses (switch presets, move the pawn, pause…).
5. Capture `NN-slug.png` into the entry folder. Repeat for each shot.
6. Look at every image before using it. Discard black frames, the Unsupported screen, and half-loaded scenes.

For **old commits** (backfill, or re-shooting history):

- `git worktree add <scratchpad>/wt-<step> <sha>`, then `pnpm install --frozen-lockfile` and the same procedure from inside the worktree.
- Remove the worktree afterwards.
- The commits are 0.1 → `b18be46`, 0.2 → `2303ca7` (which includes the resize fix), and 0.3 → `0e329e1`.

## Video procedure (goes into `devlog/README.md`)

1. Open the game in Firefox (or any browser) and go fullscreen with Cmd+Ctrl+F, so only the game is visible.
2. Record with QuickTime (File → New Screen Recording, or Cmd+Shift+5 → record entire screen / selected portion). Keep clips short (10–60 s) and show one thing per clip.
3. Save the `.mov` into the entry folder with a descriptive name (`moba-steering.mov`).
4. Commit as usual. The pre-commit hook turns it into `moba-steering.mp4` + `moba-steering.jpg` and stages both. Then reference it in the entry's Media section.

   You can also run `pnpm devlog:video` by hand to preview the result before committing.

## Implementation notes

- **Headless WebGPU works with no flags.** agent-browser 0.38 launches its own Chrome for Testing (`agent-browser install`, stored in `~/.agent-browser/`). Headless on macOS, `navigator.gpu` is there and the game renders at 60 fps. We didn't need `--headed` or `--webgpu`.
- **agent-browser has no key-down/key-up command** (`press` is a tap). Held keys are sent with `eval` as synthetic `KeyboardEvent`s on `window`, which `input/dom.ts` listens to. Mouse buttons work natively (`mouse down right`).
- **agent-browser's build script is denied** with `allowBuilds: { agent-browser: false }` in `pnpm-workspace.yaml`. Its postinstall only downloads the native binary, which the package already ships for every platform. pnpm 10.26 warned about it whatever we set. After this step we moved to **pnpm 12.6**, which turns an unanswered build script into an install error (`ERR_PNPM_IGNORED_BUILDS`) and respects `allowBuilds`.
- **The compress script needs ffprobe once any `.mp4` exists**, because it checks each `.mp4`'s tag on every run. That's ~30 ms per file. It only fails (with an install hint) when there's something to do and ffmpeg/ffprobe is missing. With no videos at all, it never shells out.
- **ffmpeg details:**
  - `-fpsmax 60` caps the frame rate without duplicating frames on 30 fps sources.
  - The poster is taken at `min(1 s, duration / 2)`, so sub-second clips still get one.
  - The script encodes to `<name>.tmp.mp4` first (gitignored and skipped by the scan), so an interrupted run never leaves a half-written tagged file.
- **Tested:**
  - a 128 MB 2560×1440/120 fps ProRes `.mov` → 0.9 MB 1920×1080/60 fps tagged MP4 + poster
  - a sub-second untagged `.mp4` is re-encoded in place
  - a re-run does nothing (0.4 s)
  - with no ffmpeg on `PATH`, it exits 1 with the brew hint
  - **end to end in a fresh clone:** `pnpm install` set up husky, and committing a `.mov` produced a commit with only the `.mp4` + `.jpg`
- **Backfill:**
  - Screenshots for 0.1 (`b18be46`) and 0.2 (`2303ca7`, including `?nowebgpu`) came from temporary worktrees running `vite` on 5748/5749.
  - 0.3 and 0.3.1 came from the current production build on 5747. `src/` hasn't changed since `0e329e1`.
  - Write-ups came from the plans, the git log and the six earlier session transcripts (summarized, never copied).
- **Added a `0.0-concept` prologue entry** (no screenshots) for the two design/planning sessions before 0.1. They hold the most important "why" of the whole project.
- **Video links use `[![poster](x.jpg)](x.mp4)`** instead of `<video>`, because GitHub doesn't render `<video>` with relative sources.
