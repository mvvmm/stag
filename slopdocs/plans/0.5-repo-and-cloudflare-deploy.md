# 0.5 Repo & Cloudflare Deploy: Implementation Plan

> Status: **done (2026-09-27).** Parent: [implementation-plan.md](../implementation-plan.md) step 0.5.

## Goal

Get the game out of a local folder and into a place where it builds, checks and deploys itself:

- a **public GitHub repo** `mvvmm/stag`, with a clean history (no secrets) and an "all rights reserved" license
- **production** on Cloudflare Workers static assets at `stag.<subdomain>.workers.dev`, deployed on every merge to `main`
- a **Worker Preview** for every PR (stable URL that follows the branch + an immutable URL per push), commented on the PR
- **required checks** on every PR: `typecheck`, `lint` (Biome lint + format), `test` (including the replay fixtures) and `build`
- a **Worker-scoped deploy token** (per-Worker RBAC, role Editor on `stag` only) for local and agent wrangler use, replacing `wrangler login`

From now on, each step is a branch + PR. You playtest the Preview, the check goes green, and a merge ships it.

Out of scope:

- custom domain (later, when the game has a real name)
- R2 assets, D1, any Worker code (static assets only, no `main` script)
- Cloudflare Access / gating (the game is open but unlisted)
- analytics, error reporting, dependency bots

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Repo | **Public, `mvvmm/stag`** | Started as private; switched to public because GitHub Free only enforces rulesets (required checks) on public repos. Build-in-the-open is a side effect: devlog and slopdocs are readable. |
| Name | **`stag`** | Matches the codename already in use (port 5746, `stag.debug`). Repo, Worker and `package.json` `name` all become `stag`. It's a codename and can change. |
| License | **All rights reserved** | `LICENSE` covers our own code and content only. Third-party assets keep their own licenses (see below). We discussed AI authorship: the notice mostly means "no permission granted". How far copyright reaches into AI-written code is unsettled, but that doesn't change the choice. |
| Third-party assets | **Tracked per asset; non-redistributable ones stay out of the repo** | Many store licenses allow shipping assets in a game but not redistributing the raw files, and a public repo counts as redistribution. CC0/CC-BY can go in the repo, with CC-BY credited in `CREDITS.md`. Anything else lives outside the repo (R2 in 9.1). The convention goes into AGENTS.md now. |
| CI/CD | **Workers Builds deploys, GitHub Actions checks** | Cloudflare's Git integration builds `main` → production and every other branch → a Worker Preview (launched 2026-09-22), and posts the URLs on the PR. Actions runs the `check` job. No Cloudflare secrets in GitHub. |
| Deploy token | **Workers Builds now, scoped token later** | Per-Worker RBAC (2026-09-15) only works on *account-owned* tokens, but Workers Builds only accepts *user* tokens so far ("account-owned support coming soon"). For now: Builds uses a hand-trimmed user token (below), and an account-owned token scoped to **Specified Workers → `stag`, role Editor** serves local/agent wrangler. |
| Workflow | **Branch + PR per step, merge commits** | Branch `<step>-<slug>`. Merge commits keep every commit and devlog links valid. `git log --first-parent main` gives one line per step. |
| Protection | **Ruleset on `main`: PR required (merge commits only), `typecheck`/`lint`/`test`/`build` + `Workers Builds: stag` required, no force-push/deletion** | The ruleset is enforced because the repo is public. The user asked for the checks to be separate jobs rather than one opaque `check`, so the PR shows what failed. |
| Observability | **Workers Logs + traces on, sampled at 100%** | Added during implementation at the user's request. An assets-only Worker never runs a script, so they stay empty until the Worker gets code. |
| Domain | **workers.dev** | Custom domain later. |
| Access | **Open, unlisted** | `robots.txt` disallows everything and every response sends `X-Robots-Tag: noindex`. Previews too. |
| Headers | **COOP/COEP everywhere** | Same as `pnpm dev`/`preview`, via `public/_headers`. The profiler gets ~5 µs timers on deployed builds. Future cross-origin assets (R2) must send CORP/CORS. |
| Preview builds | **Identical to production** | Same build, and `?debug` opens the dev tools, as in production. |
| Commit email | **Keep `root.mvm@gmail.com`, no history rewrite** | It's already public in the user's other repos (`mvvmm`, `fibole`, `vance.page`, …, `cloudflare-docs`), so hiding it here gains nothing. |
| Secrets hygiene | **One-time full-history scan + GitHub push protection + `.gitignore`** | See steps 1–2. |

### Defaults I picked (object if you disagree)

- **No bypass on the ruleset.** Small fixes go through a PR too, which is cheap because the check is fast. Admins can edit the ruleset in an emergency.
- **Four required jobs** (`typecheck`, `lint` via `biome ci`, `test`, `build`), each set up through a shared composite action (`.github/actions/setup`: Node from `.nvmrc`, pnpm from `packageManager`, cached store). It triggers on `pull_request` and on `push` to `main` (so main's status is visible too). Fork PRs work because the job needs no secrets.
- **`wrangler` is a devDependency** (≥ 4.135 for `wrangler preview`), so Builds and local use the same pinned version.
- **Workers Builds settings:** build `pnpm build`, deploy `pnpm exec wrangler deploy`, preview `pnpm exec wrangler preview`, and preview builds on for all non-production branches. Node 24 comes from `.nvmrc`, or from `NODE_VERSION` if Builds ignores `.nvmrc` (verify).
- ~~**Trimmed Builds user token**~~ **dropped:** a user token can't be scoped per Worker, so trimming only removed KV/R2/Routes while keeping edit on every Worker. The user set up Workers Builds with its own new build token instead.
- **Local deploy scripts** `pnpm cf:deploy` / `pnpm cf:preview` (build + wrangler). `pnpm deploy` is a built-in pnpm command, hence the prefix. They're for emergencies and agents; the normal path is merging. Credentials: `CLOUDFLARE_API_TOKEN` (the scoped token) + `CLOUDFLARE_ACCOUNT_ID` in a gitignored `.env`, if wrangler picks it up (verify), otherwise exported in the shell. `.env.example` documents the names.
- **Caching:** `/assets/*` (Vite-hashed) gets `Cache-Control: public, max-age=31536000, immutable`. HTML keeps the Workers default (revalidate), so a deploy is picked up on reload.
- **Build identity:** the commit (`__COMMIT__`, already defined) shows in the debug pane title and as `__game.build`, so a playtest bug report can say which build it came from. Players see nothing.
- **Enable GitHub secret scanning + push protection** (free on public repos).
- **README.md** with a one-paragraph pitch, the stack, `pnpm` commands (pointing at AGENTS.md), the live URL and a license note. It's the repo's front page now.

## Config sketch

`wrangler.jsonc` (assets-only Worker):

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "stag",
  "compatibility_date": "2026-09-27",
  "assets": { "directory": "./dist" }
}
```

`public/_headers` (Vite copies it into `dist/`):

```
/*
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: require-corp
  X-Robots-Tag: noindex
/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

`.gitignore` additions: `.env*` with `!.env.example`, `.dev.vars*` with `!.dev.vars.example`, `*.pem`, `*.key`, `.idea/` (`.wrangler` is already there).

## Steps

Steps marked 👤 need the user in a browser (dashboard or OAuth). Everything else is done by the agent.

1. **Secret audit (before anything is public).**
   - Run `gitleaks git` over the full history and the working tree.
   - Grep the history (`git log -p --all`) for tokens, `.env` content, private keys, `/Users/` home paths and anything else the devlog backfill might have leaked.
   - Look at every committed binary that isn't obviously a screenshot or video.
   - If something is found: stop and decide with the user (the history can still be rewritten safely, since nothing is published).
2. **Repo hygiene.** Update `.gitignore`; add `LICENSE` (all rights reserved, third-party assets excluded), `CREDITS.md` (empty table: asset, author, source, license) and `README.md`; rename the package to `stag`. Add the asset-license convention to AGENTS.md. Commit on `main` (the last direct commit).
3. **Create and push the repo.** `gh repo create mvvmm/stag --public --source . --push`. Enable secret scanning + push protection.
4. **CI check.** Add `.github/workflows/check.yml` (the `check` job). Push it on branch `0.5-repo-and-cloudflare-deploy` and open the PR. From here on, all work for 0.5 happens on that branch.
5. **Worker config.** Add `wrangler` as a devDependency, `wrangler.jsonc`, `public/_headers`, `public/robots.txt`, the `cf:*` scripts and `.env.example`. Show the build in the pane title and `__game.build`. Check locally with `pnpm build && pnpm exec wrangler dev` that the headers are served (`crossOriginIsolated === true`) and the game renders.
6. 👤 **First deploy (creates the Worker).** Run `wrangler login` (admin, expired right now), then `pnpm exec wrangler deploy` once from the branch. It must exist before a per-Worker token can target it. Afterwards `wrangler logout`, since the OAuth login shouldn't linger.
7. 👤 **Scoped token.** Dashboard → Manage Account → Account API Tokens → create `stag-deploy`: Workers, Specified Workers → `stag`, role Editor. Put it in `.env` (or the shell) with the account ID. Agent verifies: `wrangler whoami`, `pnpm cf:preview` works, and deploying under another Worker name is refused.
8. 👤 **Workers Builds.** Worker `stag` → Settings → Build → connect `mvvmm/stag` (installs the Cloudflare GitHub App, scoped to that repo only). Set the commands/branches from the defaults and the trimmed user token from step 7's notes (created under My Profile → API Tokens). Push to the PR branch → a Preview URL is commented on the PR.
9. **Ruleset.** `gh api` to create the `main` ruleset (PR required, `check` required, no force-push/deletion). Verify that a direct push to `main` is rejected.
10. **Verify end to end.** On the PR's Preview URL, with agent-browser:
    - the game renders with WebGPU
    - `crossOriginIsolated` is true, and `noindex` + cache headers are present (`curl -I`)
    - `?debug` opens the pane with the build commit
    - the Preview's stable URL updates after another push
11. **Docs.** AGENTS.md: repo URL, the branch + PR workflow, the required check, the `cf:*` commands and token setup, "never commit secrets" (`.env`), third-party asset rules. Update the Hosting row and tick 0.5 in `implementation-plan.md`. Add implementation notes here.
12. **Devlog + merge.** Write `devlog/0.5-repo-and-cloudflare-deploy/`: screenshots of the PR with its Preview comment and the checks, the live game on workers.dev and the pane build tag. The PR is merged (the first merge-commit merge; the user merges from now on, see AGENTS.md), then confirm production at `stag.<subdomain>.workers.dev` shows the merge commit.

## Acceptance criteria

- [x] `gitleaks` over the full history reports nothing (or every finding is explained as a false positive), and there are no home paths, keys or `.env` content in any commit.
- [x] `github.com/mvvmm/stag` is public with `LICENSE` (all rights reserved), `CREDITS.md` and `README.md`. Secret scanning and push protection are on.
- [x] `.gitignore` covers `.env*` (except `.env.example`), `.dev.vars*` (except `.dev.vars.example`), `.wrangler`, keys.
- [x] Every PR runs `typecheck`, `lint` (Biome lint + format), `test` (incl. replay fixtures) and `build`. `main` can't be pushed to directly or merged into with a red check.
- [x] Every PR gets a Worker Preview URL commented by Cloudflare. The stable URL follows the latest push.
- [x] Merging to `main` deploys production to `stag.<subdomain>.workers.dev` with no manual step.
- [x] Deployed builds render with WebGPU, have `crossOriginIsolated === true` and send `X-Robots-Tag: noindex`. `robots.txt` disallows all, and `/assets/*` is immutable-cached.
- [x] `?debug` works on production and Previews, and the pane shows the build commit.
- [x] Local wrangler uses an account-owned token scoped to the `stag` Worker (Editor). `wrangler login` is not needed and is logged out.
- [x] Workers Builds uses a dedicated build token set up by the user (the trimmed token was dropped, see Defaults).
- [x] AGENTS.md documents the workflow, commands, token setup and asset-license rules. 0.5 is ticked, and the devlog entry is in the merge.

## Implementation notes

- **Secret audit:** gitleaks 8.30 over all 24 commits and the working tree found nothing. A grep of `git log -p` for keys, tokens, `.env` content and home paths found only `~/.claude/projects/-Users-mvm-code-game` in the 0.3.1 plan (the username "mvm", harmless). The devlog MP4s were already stripped of metadata by `devlog:video`. The only personal detail in the media is the Mac's name ("vance's Ma…") in the 0.4.2 walkthrough's file dialog, and the user's `vance.page` repo already makes that name public.
- **Commit email:** the user asked why commits didn't use their GitHub login. `gh` auth only covers pushes, and authorship comes from `git config user.email`. Their other public repos already use the same gmail, so we kept it and didn't rewrite history.
- **Cloudflare API vs. dashboard:** the Cloudflare MCP connection (OAuth) can manage Workers Builds end to end: `POST /builds/workers` with `script_tag`, `git_repository` (GitHub numeric owner/repo ids), `production_settings`, `previews_enabled`, `previews_base_config`. It gets 9109 on every API-token endpoint, so tokens have to be created in the dashboard. Claude in Chrome wasn't connected, and a headed agent-browser login was declined, so the user created `stag-deploy` themselves and set up the Builds token.
- **The scoped token can't register itself as a Builds token.** `POST /builds/tokens` authenticated with the per-Worker token → 403. That's expected, but it means a caller with Builds permissions would have to handle the secret. We didn't push further.
- **`wrangler preview` needs a `previews` block** in `wrangler.jsonc`, even an empty one. The first Preview build failed on it. It's there now.
- **Workers Builds picked up Node 24.21 from `.nvmrc` and pnpm 12.6 from `packageManager`** with no build variables. The `allowBuilds` entries for esbuild/workerd (needed once wrangler was added, or pnpm 12 fails with `ERR_PNPM_IGNORED_BUILDS`) work there too.
- **First deploy:** `wrangler deploy` with the user's OAuth login created the Worker (a per-Worker token can't target a Worker that doesn't exist yet), then `wrangler logout`. The workers.dev subdomain turned out to be `root-mvm`, not `mvvmm`.
- **Scoped token verified:** `wrangler deployments list --name stag` works, `--name hello-world` is refused, and `pnpm cf:preview` deploys a Preview. Wrangler reads it from `.env` ("Account API Token … read from the CLOUDFLARE_API_TOKEN environment variable").
- **Ruleset verified:** a direct push to `main` was rejected with GH013. Only merge commits are allowed, and branches are deleted on merge.
- **Preview URLs:** stable `https://<branch-slug>-stag.root-mvm.workers.dev` (dots become dashes), and per commit `https://<id>-stag.root-mvm.workers.dev`. Cloudflare keeps a single PR comment updated, with one row per build.
- **Naming:** the user wants `stag` everywhere possible, so `package.json`, `solo.yml`, the page `<title>` (was "Druid") and the Worker all use it. The local folder is still `~/code/game`.
