# 1.1 Grey-box Arena: Implementation Plan

> Status: **done (2026-09-27).** Parent: [implementation-plan.md](../implementation-plan.md) step 1.1.

## Goal

The first real place to stand in: a hand-built, combat-sized grey-box room with walls, blocks and pillars, seen through the angled top-down camera, which now follows the pawn:

- **Room data** in `src/data/rooms/`: bounds, obstacles (circles and rotated boxes with a height), spawn point. It's plain TS data, Babylon-free.
- **An `arena` scene** whose `spawn` turns the room into static obstacle entities plus the demo pawn, and whose view builds grey-box meshes from those entities.
- **Camera:** a new `yaw` tunable next to pitch/distance/FOV, and a hard follow of the pawn.
- **Occluder fading:** obstacles that hide the pawn fade out while they do.

When it's done, `pnpm dev`, production and the Preview all start in the arena. You can walk the demo pawn around it with either preset. It walks through walls until 1.3. `pnpm check` must pass.

Out of scope:

- the real player controller (1.2), collision (1.3), camera smoothing/look-ahead/bounds (1.4)
- lighting, fog, shadows, post (1.5). The current simple lights stay.
- doors, multiple rooms, chamber flow (6.2), procedural layout (8.1)
- a room editor. Rooms are edited as TS data, and a reload shows the change.

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Arena data | **Room data + sim entities** | The layout is data in `src/data/rooms/`. The arena scene's `spawn` turns each obstacle into a static ECS entity. The view builds meshes from those entities. So 1.3 collision reads the same entities headlessly, and replays, snapshots and the entity picker all see the walls. |
| Layout | **~30×20 m rectangle + mixed cover** | Tall perimeter walls, a few round pillars, a couple of box blocks, low walls (one diagonal), and one tight gap between obstacles. Scattered unevenly so it doesn't read as a test grid. Spawn is near the center. |
| Shapes | **Circles + rotated boxes** | `circle { x, z, r }` and `box { x, z, w, d, yaw }`, each with a `height`. Collision (1.3) is 2D and ignores height. Height is for the view now, and later maybe for line of sight/projectiles. |
| Actor | **Reuse the demo pawn** | The throwaway pawn (constant speed, WASD / right-click-to-move) spawns at the room's spawn point to judge scale and camera. It passes through walls until 1.3. 1.2 replaces it. |
| Camera yaw | **New `camera.yaw` tunable, default 0°** | Screen-aligned (V Rising / League). Walls line up with the screen and WASD maps cleanly. 45° (Hades-style diamond) can be tried in the pane. |
| Camera target | **Hard-follow the pawn** | Target = the pawn's interpolated position, no smoothing. The camera code takes a target, which 1.4 smooths and clamps. |
| Look | **Flat greys + 1 m floor grid** | Faint 1 m lines, brighter every 5 m, for judging distance and speed in 1.2/1.7. Tall walls, low walls, blocks and pillars in distinct flat greys; no textures. |
| Scenes | **Arena is the default; demos stay** | `arena` becomes `DEFAULT_SCENE`. Input test and stress stay in the dev switcher (stress is the 9.6 benchmark). The input test goes once 1.2 replaces the pawn. |
| Occlusion | **Occluders fade, whole mesh** | An obstacle whose mesh covers the pawn on screen fades smoothly to ~25% alpha and back. A long wall fades completely even if only its tip covers the pawn. That's acceptable for grey-box; a see-through hole can come with the art pass if needed. |

### Defaults I picked (object if you disagree)

- **Units are meters**, +X east, +Z north (away from the camera at yaw 0), and the ground at `GROUND_Y = 0`.
- **Room data shape** (`data/rooms/room.ts`, types + helpers; `data/rooms/greybox.ts`, the room):
  ```ts
  type ObstacleKind = "wall" | "low" | "block" | "pillar"; // picks the grey-box material
  type ObstacleShape =
    | { kind: "circle"; x: number; z: number; r: number }
    | { kind: "box"; x: number; z: number; w: number; d: number; yaw: number }; // w along X, d along Z before yaw
  type Obstacle = { type: ObstacleKind; shape: ObstacleShape; height: number };
  type Room = { id: string; width: number; depth: number; spawn: Vec2; obstacles: Obstacle[] };
  ```
  The room is centered on the origin. Perimeter walls are ordinary obstacles, made by a `perimeterWalls(width, depth, { thickness, height })` helper in the room data, so a later room can leave a gap for a door. Heights: tall walls 3 m, low walls 0.6 m, blocks 1.5 m, pillars 3 m (4 m loomed too large near the bottom of the screen).
- **ECS:** one new component, `obstacle: { type, shape, height }` (plain data, copied from the room). Obstacles have **no `transform`**: they never move, need no interpolation, and mesh sync (which gives every `transform` entity a box) leaves them alone. One `room: { id, width, depth }` entity carries the floor size for the view. The entity list labels them `#id obstacle` / `#id room`.
- **Picking obstacles:** the view builds their meshes, so the scene registers them with a new `ctx.bindMesh(entity, mesh)`. `meshOf`/`entityOf` (and so the picker and entity pane) then work for them the same as for synced meshes. The binding is dropped at teardown.
- **Obstacle meshes:** a cylinder for a circle and a box for a box, bottom on the ground. There's one shared material per `ObstacleKind`, and all meshes are frozen (`freezeWorldMatrix`), since they're static. No instancing yet (9.6).
- **Floor:** a ground plane the size of the room plus a margin, so the void past the walls isn't visible at normal pitches. Its material is a small **WGSL `ShaderMaterial`** that draws the grid from world position. Babylon's `GridMaterial` (`@babylonjs/materials`) is GLSL-only, and on WebGPU that means fetching the GLSL→WGSL converters from a CDN at runtime. The grid colors and line widths are constants, not tunables (they're throwaway until 1.5).
- **Camera:** `updateCamera(camera, target)` places the camera at `target + offset(pitch, yaw, distance)` and looks at the target. `camera.yaw` is in degrees (−180 to 180, step 1). The scene provides the target through a new `ctx.setCameraTarget(() => Vec3)`. The arena returns the pawn mesh's interpolated position. Scenes that don't set a target keep looking at the origin (input test, stress). Order in the shell:
  - The camera is placed **right before rendering**, after mesh sync, so it follows the interpolated pawn without a frame of lag.
  - Aim and WASD yaw still read the camera at the start of the frame, i.e. the camera from the last rendered frame, which is what was under the cursor. So aim stays correct while the camera moves.
  - The debug free camera ignores the target, as before.
- **Occluder fading** (`render/occlusion.ts`, view-only, on the game camera only):
  - Once per frame, cast a few rays from the camera to points on the focus: the pawn's center, head and left/right edges on screen. Any obstacle mesh they hit before the focus is an occluder. Rays test only obstacle meshes, which is cheap at this count.
  - Each obstacle mesh's `visibility` eases toward `occlusion.alpha` (default 0.25) while it occludes, and back to 1 when it doesn't, over `occlusion.fade` seconds (default 0.15). The easing runs on frame time, since it's view-only.
  - Obstacle materials need `needDepthPrePass` (or `forceDepthWrite`) so a faded wall doesn't sort badly against itself. We'll check how it looks.
  - Tunables: `occlusion.alpha` (0–1), `occlusion.fade` (0–1 s), and `occlusion.enabled` (a checkbox, so the difference can be compared).
- **Debug draw:** the arena draws each obstacle's 2D footprint (circle/box outline) under the category `obstacles`. That's handy for checking the data now and 1.3's collision later. It's drawn from the view in `onFrame` (debug draw is write-only, so it may also come from the sim later).
- **Replays:** add one arena replay fixture (walk around for a few seconds with both presets) so the scene's spawn is covered headlessly. `pnpm replay:update` refreshes it when 1.2 changes the pawn.
- **Scene files:** `scenes/arena.ts` (sim: pawn system, `spawn` from a room) and `scenes/arena.view.ts` (setup). The arena isn't throwaway, so it lives in `scenes/`, not `demo/`. The pawn system and component stay where they are until 1.2.

## Architecture

```
data/rooms/
  room.ts          Room / Obstacle / ObstacleShape types, perimeterWalls()          (pure, tested)
  greybox.ts       the 30×20 grey-box room
ecs/world.ts       + obstacle, room components
scenes/
  arena.ts         arenaSim: systems [pawn], spawn(room → room + obstacle entities + pawn)  (spawn tested)
  arena.view.ts    floor + grid, obstacle meshes (bindMesh), camera target, occlusion, footprint debug draw
  scene.ts         + ctx.bindMesh(entity, mesh), ctx.setCameraTarget(fn)
  index.ts / sims.ts  + arena, default "arena"
render/
  scene.ts         createScene without the hardcoded ground; camera.yaw; updateCamera(camera, target)
  meshSync.ts      + bind(entity, mesh) for externally built meshes (meshOf/entityOf)
  gridMaterial.ts  WGSL ShaderMaterial for the floor grid
  occlusion.ts     per-frame occluder rays + visibility easing, occlusion tunables
shell.ts           camera target from the scene, camera placed after mesh sync
replay/fixtures/   + an arena fixture
```

Rule 1 holds: `data/`, `ecs/` and `scenes/arena.ts` stay Babylon-free. Only the `.view.ts`, `render/` and the shell touch Babylon.

## Steps

1. Room types, `perimeterWalls`, and the grey-box room data, with tests: shapes are valid (positive sizes, finite numbers), every obstacle is inside the room bounds, the spawn is clear of every obstacle footprint, and the perimeter is closed.
2. `obstacle` + `room` components; `scenes/arena.ts` sim with `spawn` (room entity, obstacle entities, pawn at the spawn point). Test that spawn produces the right entities from a room.
3. Camera: `camera.yaw` tunable, `updateCamera(camera, target)`, `ctx.setCameraTarget`, and the shell places the camera after mesh sync. Move the hardcoded ground out of `createScene` (the demos get their own ground in their setup).
4. `render/gridMaterial.ts` (WGSL) and the arena view: floor, obstacle meshes per kind, `bindMesh`, footprint debug draw, and the pawn as the camera target. Register the arena and make it the default.
5. `render/occlusion.ts` + tunables; wire it into the arena view. Check the look (depth pre-pass, sorting) in the browser.
6. Record the arena replay fixture. `pnpm check`, `pnpm build`.
7. Verify in agent-browser (acceptance below), and tune the room layout and camera defaults by looking at screenshots.
8. Docs:
   - AGENTS.md: layout (`data/rooms/`, `scenes/arena*`), `ctx.bindMesh` / `ctx.setCameraTarget`, the arena as the default scene
   - implementation notes here, tick 1.1 and link this plan, devlog entry `devlog/1.1-grey-box-arena/` (several screenshots: overview, a few camera angles, occluder fade, obstacle debug draw)
   - commit "Grey-box arena (1.1)", push the branch, open a PR, get the checks and Preview green, and report the Preview URL (the user merges)

## Acceptance criteria

## Implementation notes

- **Verified in headless Chrome** (agent-browser, real WebGPU) on the dev server and the production preview:
  - The production build ignored `?scene=stress`, started the arena and had no `__game`.
  - The camera follows the pawn. With the pawn behind the south pillar, the pillar went to 0.25 visibility. Next to the south perimeter wall, the wall faded instead. Behind the angled tall wall segment, that wall faded.
  - At `camera.yaw` 45 the room turns into a diamond, and the `obstacles` footprints line up with every mesh, including the rotated boxes (so our `yaw` matches Babylon's `rotation.y`).
  - `__game.select` on an obstacle outlined it and showed `Entity #7 obstacle` with its type, shape and height in the entity pane.
  - 20 switches between arena, input test and stress left meshes, materials and render observers exactly where they started (20 / 10 / 1).
  - The `arena-walk` fixture (four right-click moves in `moba`, then W/A/S/D in `mmo`, 524 ticks) plays back to the end without divergence in the browser and in `pnpm test`.
- **Played by hand** on a 120 Hz display in Firefox (the devlog video): the follow and aiming held up. Headless only runs at 60 fps.
- **The floor is darker outside the room.** Once the camera followed the pawn to an edge, the grid past the walls looked just like the floor inside. The grid shader now takes the room's half size: outside it's darker and has only faint 5 m lines.
- **Obstacles have no `transform`.** Mesh sync gives every `transform` entity the demo box, and obstacles never move. Their position is in `obstacle.shape`, and the arena view builds and `bindMesh`-es their meshes (mesh sync doesn't dispose bound meshes; the scene owns them).
- **Editing an obstacle in the entity pane changes the sim data but not its mesh**, which is built once at setup. That's fine until 1.3 reads it for collision. Live layout editing would be a room editor, which is out of scope.
- **Fading uses `mesh.visibility`,** so the materials stay shared per obstacle type. Convex boxes and cylinders with backface culling sort fine without a depth pre-pass.
- **The camera is placed after mesh sync.** Aim still projects through the camera as the last frame rendered it, which is what the cursor points at.
- **The main chunk is still ~6.8 MB** (1.49 MB gzipped), the same as `main` (+6 KB). That's the `@babylonjs/core` root import, which is the 9.6 performance pass's job.

## Revision: debug pane and input fixes from playtesting

While playing the arena, you asked for these (same PR):

- **Pane layout.** Loop became **Time** (pause, step, tick, time scale, interpolation). The control preset moved to a new **Gameplay** folder, where cheats like infinite health go later. The Debug draw folder and its master switch are gone: **View** now holds everything that paints on the screen, with one toggle per debug-draw category, and the Babylon Inspector button at the bottom.
- **Debug draw is always recording in debug builds**, and new categories start hidden. Categories only appear once something draws, so a master switch would have hidden them all until you turned it on. The `draw.toggle` command and the stored `draw.enabled` setting are gone (old settings still load).
- **The input overlay works in every scene.** Only the input-test scene used to feed it, so it went quiet when the arena became the default. It now lives in the dev tools (`debug/inputOverlay.ts`), and press counts start over on each load.
- **The pane no longer steals the keyboard.**
  - The input layer only ignores keys typed into text fields. A focused checkbox, button or dropdown no longer blocks game keys, and a bound key can't pick a dropdown option by its letter.
  - After a click, the pane gives focus back (dropdowns once they have a value). Text fields keep focus until Enter.
- **Stuck keys after a dropdown.**
  - The cause, found from a replay: D stayed held for the rest of the recording. On macOS, a native dropdown list swallows every key event while it's open, so a key released meanwhile never gets a keyup.
  - The fix: pressing the mouse on a dropdown releases every held key and button. It applies only to dropdowns; other pane controls leave held keys alone.
- **Auto-pause lifts without a `focus` event.** The frame loop re-checks `document.hasFocus()`, so the game unpauses as soon as the page has focus again.
