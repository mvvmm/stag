# 0.4.1 Scenes & Reset: Implementation Plan

> Status: **done (2026-09-27).** Parent: [implementation-plan.md](../implementation-plan.md) step 0.4.1. Starts from the [decisions carried over from 0.4](0.4-dev-tooling.md#decided-for-041-and-042).

## Goal

Make the game restartable in place and give the dev tools a handle on scenes and entities:

- a **scene registry**: each scene declares its systems and a setup, and the pane switches between them
- an **in-place reset** (no page reload) that tears the running scene down completely and sets it up again: fresh world, reseeded RNG, tick count 0. The engine, pane, Inspector and free camera stay open. 3.5 (death & restart) and 6.3 (room transitions) reuse it, so it lives in the shell, not in `debug/`
- **seed display + restart** with the same seed or a new one
- **frame step** while paused
- an **entity picker**: select an entity in the world or from a list, see its components live in the pane, edit them, and highlight the selection with debug draw

When it's done, `pnpm dev` opens the last-used scene. The pane has a Scene folder (scene, seed, restart), a Step button, and an Entity folder with a pick toggle and live components. A second **stress scene** exists next to the input test. `pnpm check` must pass.

Out of scope:

- record & replay, checksums (0.4.2)
- the real arena (1.1), death & restart (3.5), room transitions (6.3): they get the reset API from this step
- Vite HMR of scenes (a full reload is fine for now)
- a player-facing scene or seed UI

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Scene shape | **Scene declares its systems** | `SceneDef = { id, label, systems: NamedSystem[], setup(ctx) }`. The simulation is rebuilt from the scene's systems on every load/reset, so each scene runs only what it needs. The global `defaultSystems` list goes away. The arena (1.1) and later the run (6.x) are just more scenes. |
| Teardown | **Tracked scene context** | `setup(ctx)` gets a per-load `SceneContext` whose helpers register their own cleanup: `ctx.onTick`, `ctx.onFrame`, `ctx.onBeforeRender`, `ctx.own(disposable)`, `ctx.onTunableChange`. A teardown disposes everything tracked (in reverse order) and drops the world. That makes a forgotten cleanup hard to write. |
| Second scene | **Stress scene** | N orbiting boxes (`stress.count` tunable) running only the orbit system. It proves switching and per-scene systems, and gives the profiler and the 9.6 perf pass a ready benchmark. |
| URL | **Debug-only, read-only** | `?scene=` and `?seed=` are read once at startup and only when `DEBUG` is on. The game never writes the URL. Players never deal with URLs. |
| Reload | **Last scene, fresh seed** | `stag.debug` remembers the last scene picked in the pane. The seed is rolled fresh on every load unless `?seed=` pins it. |
| Picking | **Pick toggle + entity list** | A "pick" checkbox borrows the mouse the way the free camera does: while it's on, canvas clicks select entities and don't reach the game (the keyboard still does). A dropdown lists entities for the ones that are hard to click or have no mesh. |

### Pane layout (changes)

| Folder | Controls |
|---|---|
| **Scene** (new, top) | scene (dropdown), seed (text: edit + Enter restarts with it), Restart (same seed), New seed |
| Loop | + Step one tick (pauses first if running), + tick (read-only) |
| **Entity** (new) | pick in world (checkbox), selected (dropdown) |
| **Entity pane** (new, separate panel left of the main pane, only while something is selected) | Deselect, then one folder per component of the selection |

### Defaults I picked (object if you disagree)

- **A reset creates a fresh `World`.** miniplex has no `clear()`, and its `world.id()` counter never goes back to 0. A new world per load gives ids that start at 0 on every run, which replays (0.4.2) and "entity #7" in the pane can rely on. `shell.world` and `__game.world` become getters, so holders never keep a stale world. Mesh sync is rebuilt per world and disposes its meshes.
- **Load sequence** (`shell.load(sceneId, seed)`; `shell.restart(seed?)` reloads the current scene):
  1. dispose the old scene context (listeners, observers, owned meshes/materials), dispose mesh sync
  2. new `World`, `createRng(seed)`, `createSimulation(world, rng, def.systems, { around })`, new mesh sync
  3. `loop.reset()`: accumulator and tick count to 0; `paused` and `timeScale` are kept
  4. `input.resetEdges()`: latched presses/releases and the move command are dropped; physically held keys stay held
  5. `debugDraw.clear()`: tick and duration shapes are dropped
  6. `def.setup(ctx)`, then `onLoad` listeners (dev tools: selection, pane refresh)
- **What survives a reset:** paused state (reset while paused sits at tick 0, ready to step), time scale, interpolation, input preset, tunables, free camera, wireframe, debug-draw settings, the pane and the Inspector. The selection is cleared.
- **Seeds** are uint32, rolled from the wall clock in the shell (the only place allowed to read it). The seed field accepts a decimal number, and invalid input is rejected (the field reverts). "New seed" rolls a fresh one. `console.info` logs `scene <id> seed <n>` on every load.
- **Registry** lives in `src/scenes/` (`scene.ts`: `SceneDef`, `SceneContext`; `registry.ts`: the list and `DEFAULT_SCENE`). Scene definitions stay in `src/demo/` while they're throwaway (`inputTest.ts`, `stress.ts`). Production builds always start `DEFAULT_SCENE` (the input test until 1.1) and ignore stored and URL values.
- **An unknown scene id** (from `?scene=` or a stale stored value) falls back to the default with a `console.warn`.
- **Stress scene:** `stress.count` (default 500, 10–5000, step 10). Changing it restarts the scene with the same seed, so the slider gives a quick load curve. (Implemented as a per-frame check rather than `ctx.onTunableChange`, so a slider drag restarts at most once per frame.) It reuses the orbit system and the shared box mesh from mesh sync. Deliberately no instancing: that's what 9.6 measures against.
- **Frame step** runs exactly one tick through the normal path (input sampled, debug draw begin/end, tick listeners), then publishes stats. It's a pane button in the Loop folder, and `loop.step` for `__game.run`. Stepping while running pauses first, so the button is always enabled. The loop gets a `step()` that runs one `update(dt)` and counts it even while paused.
- **Picking details:**
  - The pick toggle and the free camera both borrow mouse buttons. The game's mouse comes back only when neither is on.
  - A click is a left press + release within 4 px, so with the free camera on too, a drag still orbits and a click still picks.
  - It picks through the rendering camera with `scene.pick`, limited to entity meshes, and maps mesh → entity through mesh sync (`shell.entityOf(mesh)`). A click on nothing deselects.
  - The selection is an entity reference. It's cleared when the entity is removed or the scene resets.
- **Highlight:** a Babylon `HighlightLayer` outline around the mesh: pale for the entity under the cursor while picking, magenta for the selection. (The first version drew a debug-draw ring and `#id` label; see the revision below.)
- **Entity list:** labels are `#id comp1 comp2` (e.g. `#5 pawn`, listing components other than `transform`/`prevTransform`). The list is capped at the first 200 entities so the stress scene doesn't build a 5000-item dropdown. Picking reaches the rest. It's rebuilt when entities are added or removed (checked on the pane's 250 ms refresh).
- **Component view:** built by reflection, no per-component code:
  - numbers become number fields, booleans checkboxes and strings text fields
  - plain objects become nested folders (`transform › position › x`)
  - `null`/`undefined`, arrays and anything else show as read-only JSON text
  - the folders are rebuilt when the entity's set of components changes, and values refresh at the pane's 250 ms rate
- **Editing:** edits write straight into the component object. An edit to `transform` also snaps `prevTransform`, so it doesn't smear across a frame. Systems may overwrite edits on the next tick, which is expected (pause first to poke at state). Edits are sim mutations from outside the input stream: 0.4.2 must record them, or mark the replay as tainted.
- **`window.__game` additions:** `scenes: { list(), current(), load(id, seed?), restart(seed?) }` (named `scenes` because `scene` is the Babylon scene), `seed`, `select(entityOrId | null)`, `selected`. New commands: `scene.restart`, `scene.newSeed`, `loop.step`, `pick.toggle` (all `button: false`, since they mirror pane controls).
- **Persistence:** `stag.debug` gains an optional `scene` field. It stays `v: 1`, because a missing field just means the default. The pick toggle isn't remembered (like the free camera).

## Architecture

```
core/
  loop.ts          + reset(), step()                                                    (pure, tested)
  debugDraw.ts     + clear()                                                            (pure, tested)
input/
  state.ts         + resetEdges(); setMouseButtons becomes borrow-counted or keyed per borrower (tested)
scenes/
  scene.ts         SceneDef, SceneContext (tracked disposables/listeners)            (tracking tested)
  registry.ts      scene list, DEFAULT_SCENE, findScene(id)                            (tested)
systems/
  simulation.ts    no global defaultSystems; systems come from the scene
render/
  meshSync.ts      + dispose(), entityOf(mesh)
shell.ts           load(id, seed) / restart(seed?), world/rng getters, onLoad, entityOf, current scene + seed
demo/
  inputTest.ts     becomes a SceneDef using ctx helpers
  stress.ts        new: stress scene + stress tunables
debug/
  persist.ts       + scene field
  startup.ts       pure: pick scene + seed from URL params / stored settings / defaults    (tested)
  inspect.ts       pure: component → field tree for the pane (kinds, read-only, paths)  (tested)
  picker.ts        pick toggle: mouse borrowing, click detection, scene.pick → entity, selection
  devtools.ts      scene/seed/step/pick tools, commands, __game additions, selection highlight
  pane.ts          Scene folder, Loop tick + Step, Entity folder
main.tsx           resolves startup scene + seed, calls shell.load
```

Rule 1 still holds. `scenes/` and `demo/` touch Babylon (they're glue, like the shell). The simulation, `core/` and `input/` stay Babylon-free.

## Implementation notes

- **Verified in headless Chrome** (agent-browser, real WebGPU) on the dev server and the production build:
  - Restarting with the same seed gave identical positions at tick 0, and seed 99 a different layout. 30 steps while paused moved the tick count 0 → 30.
  - After 60 switches between the input test (6 entities) and the stress scene (500), the scene was back to 10 meshes, 6 materials and 1 render observer. The heap stayed flat over three rounds of 40 switches (GC noise only).
  - `stress.count` 1200 restarted with 1200 boxes. The profiler showed `orbit` but no `pawn`.
  - Picking the pawn selected `#5 pawn`, turned debug draw on, and didn't reach the game. A click on empty ground deselected. Pick and the free camera together: a drag orbited without picking, and the mouse came back only after both were off.
  - Typing 3.5 into `position.x` moved the pawn and snapped `prevTransform`. The seed field restarted with 777, and `abc` reverted.
  - `?scene=stress&seed=123` loaded that scene and seed. A plain reload returned to `stress` with a fresh seed. `?scene=nope&seed=abc` warned twice and started the input test. The production build ignored both params and had no `__game`; with `?debug` it honored them.
- **Babylon defers `Observable.remove`** (it unregisters on the next macrotask). Right after a burst of synchronous loads, the observer count looks inflated; it settles a moment later.
- **miniplex hands out entity ids lazily** (`world.id()` assigns on first ask). The pane asks for every entity in world order on each refresh, so ids follow spawn order. Replays (0.4.2) shouldn't depend on ids unless something assigns them deterministically.
- **Loads during a frame wait for the frame to end** (`ctx.restart()` from a frame or tick listener), so one frame never runs across two worlds. Loads from the pane or console are immediate.
- **`setMouseButtons` became `borrowMouse(owner, on)`**, keyed by borrower (`freeCamera`, `picker`).
- **The input overlay signal is nullable.** The input test clears it on teardown, so the overlay hides in scenes that don't publish input.
- **Selecting turns debug draw on**, since the highlight is debug draw. The component view hides `prevTransform` (render bookkeeping).
- `debugDraw.clear()` already existed from 0.4. `randomSeed()` lives in the shell, the only place allowed to read the clock, and also mixes in `Math.random` (the shell isn't simulation code).
- **Not yet verified by hand:** clicking through the pane in a real browser (the checks drove it through DOM events and `__game`).

## Revision: hover highlight and a separate entity pane

After trying the first version (same day), you asked for:

- **hover feedback while picking**, and a different highlight for the selection
- **the selection's components in their own panel**, there only while something is selected

What changed:

- **The picker tracks hover.** It re-picks under the cursor once per frame while picking is on (meshes move under a still cursor) and exposes `picker.hovered`.
- **The highlight is a `HighlightLayer`**, a thin screen-space outline with the inner glow off: pale cream on hover, magenta on the selection. It's created on the first highlight, so the extra render passes cost nothing until the picker is used. Mesh `renderOutline` was tried first, but it extrudes along face normals, so on a box it only showed on a couple of edges. The debug-draw ring and label are gone, and selecting no longer turns debug draw on.
- **The highlight layer warms up at startup.** On first use it imports its WGSL shaders and builds effects, render targets and pipelines. Done on the first hover, that froze a frame and flashed the whole screen with the outline color (seen in your browser, not reproducible in headless Chrome). The dev tools now create the layer right away and render a speck of a mesh through it with the outer glow off (so nothing is composed on screen). Real meshes join only once `isLayerReady()` and the mesh's `isReady()` have held for a few frames, with a ~5 s cap. With no meshes in it, the layer costs nothing.
- **The debug-draw rendering group keeps the stencil.** It cleared depth *and* stencil to draw on top, which erased the highlight layer's stencil mask and turned the outline into a solid fill whenever debug draw was on. It now clears depth only.
- **`debug/entityPane.ts`** is a second Tweakpane panel docked left of the main pane, titled with the entity (`Entity #5 pawn`). It holds Deselect and the component folders. It shows only while something is selected, and hides with the main pane (<kbd>`</kbd>) and while the Inspector is open. The main pane's Entity folder keeps the pick toggle and the dropdown.

## Fix: no way back from the Inspector (from 0.4)

The pane steps aside while the Babylon Inspector is open (it docks panels on both sides of the page). But the Inspector button lives in the pane, and <kbd>`</kbd> only toggled a pane that stayed hidden, so once the Inspector was open there was no way to close it. Now a small "Close Inspector (`)" button shows at the top center, over the game view, while the Inspector is open. <kbd>`</kbd> also closes the Inspector first when it's open, and otherwise hides/shows the pane as before.
