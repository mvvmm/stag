# 0.4.2 Record & Replay: Implementation Plan

> Status: **done (2026-09-27).** Parent: [implementation-plan.md](../implementation-plan.md) step 0.4.2. Starts from the [decisions carried over from 0.4](0.4-dev-tooling.md#decided-for-041-and-042).

## Goal

Make every debug session reproducible, tick for tick:

- **always-on recording** from each scene load: seed, scene, the tunables at tick 0, per-tick `InputFrame`s, and every out-of-band sim mutation (tunable changes, entity-pane edits, sim-affecting debug commands)
- **per-component checksums** every second, so playback reports "diverged at tick N in `pawn`" instead of drifting silently
- **save/load** as gzipped JSON (download, file picker, drag-and-drop, and in `pnpm dev` "Save as test…" straight into the repo)
- **playback** through the in-place reset, with pause, step, time scale, a timeline to seek (including backwards), and **take over** to play on live from any tick
- **headless regression tests**: replays checked into the repo run in Vitest and check every checksum. `pnpm replay:update` rewrites checksums after intentional changes.

### Why (the scope discussion)

The user was skeptical about the effort vs. the benefit this early, and chose the full version after weighing it. What it buys:

1. **Reproducing hard-to-reproduce bugs** (a charge clipping a pillar, a pounce stuck on a corner): save right after it happens, then replay, pause, step and pick entities at the exact tick.
2. **Regression tests from real play**, with no hand-written setup. Most valuable for combat, AI and augment interactions.
3. **Determinism guard:** checksums catch `Math.random`, unstable iteration or frame-rate leaks the moment they're introduced, not when seeds stop reproducing in Phase 8.
4. Tuning comparisons and devlog material, which are nice but secondary.

Cost: replays are only valid for the code they were recorded on (that's by design), and every new out-of-band sim mutation has to go through the recorder. The payoff grows from Phase 3 on. It's built now while the sim is small and the architecture is fresh.

Out of scope:

- rolling-window / keyframe recording ("save the last 2 minutes"), which would need world serialization
- replays that survive code changes (no versioned sim, no input remapping between builds)
- player-facing replays, sharing, or re-rendering replays from other cameras
- recording in player builds (only when `DEBUG`)

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Scope | **Full**, as decided in 0.4 | Plus seeking, take over and headless tests, which were "later" before. |
| Recording span | **Since the last load, capped at 60 min** | Each load or restart starts a fresh recording at tick 0. At 216,000 ticks recording stops, and the pane shows "recording full (60 min)". Saving still works. Auto-pause already stops ticks in hidden or unfocused tabs. |
| Input format | **Quantized + gzip** | `sampleTick` quantizes aim, move and the move command to a 1/1024 grid, so live play and replay see identical, exactly representable values, stored as integers. Files are `.replay.json.gz` (~1 MB per hour of active play). Loading accepts `.gz` or plain `.json`. |
| Checksums | **Per-component, every 60 ticks** | At every 60th tick and the final tick: entity count, RNG state, and one hash per component type. Floats are hashed by their exact bits, and `prevTransform` is skipped (derived). A mismatch reports the tick and the components that differ. |
| Tunables | **Recorded, then restored** | The file stores every tunable at tick 0 plus each change with its tick. Playback snapshots your values, applies the recording's, and restores yours on exit. Nothing from a replay persists to `stag.debug`. |
| Playback end | **Pause at end + Take over** | Playback pauses on the last tick. "Take over" (any time) hands control to live input at the current tick. The live recording continues from the replay's data up to that tick. |
| Seeking | **Jump to tick + step back** | A timeline slider, a tick field and "step back". Seeking backwards reloads and fast-forwards without rendering, and forward seeks fast-forward from the current tick. The divergence report has "jump to last good checkpoint". |
| Headless tests | **Yes, with a scene split** | `SceneDef` is split into a Babylon-free sim part (`spawn(world, rng)`) and a view part (`setup(ctx)`). `runReplay(file)` runs in Node. Replays in `src/replay/fixtures/` become tests automatically. |
| Stale replays | **`pnpm replay:update`** | Re-runs each fixture's inputs headless and rewrites its checksums (inputs stay as recorded), like a snapshot update. Files store the commit they were recorded on, and loading one from another commit in the browser shows a notice (not an error). |
| Saving | **Download + "Save as test…"** | "Save replay" always downloads (works in production `?debug`). In `pnpm dev`, "Save as test…" asks for a name and writes to `src/replay/fixtures/` through a dev-only Vite middleware. |

### Pane layout (changes)

| Folder | Controls |
|---|---|
| **Replay** (new, below Scene) | *Recording:* length (mm:ss, ticks), status (recording / full / playing), Save replay, Save as test… (dev only), Load replay… (file picker), checked-in replays (dropdown, dev only) |
| | *While playing:* timeline slider (ticks), tick field, Step back / Step, Take over, Exit replay, divergence status (✓ in sync so far / ✗ diverged at tick N in `pawn`, `transform`) + "Jump to last good checkpoint" |

Pause, frame step and time scale stay in the Loop folder and work during playback unchanged.

### Defaults I picked (object if you disagree)

- **Recording lives in the debug chunk** (`debug/replay/`), attached before the first `shell.load`, which already happens in `main.tsx`. Players never record.
- **Events are keyed by the tick they precede.** Tunable changes and edits happen between ticks (during a frame). They're recorded as "before tick T", and playback applies them right before stepping tick T. That matches what live play did.
- **Tick-0 tunables are applied before `spawn`**, because setups read tunables (e.g. `stress.count`). The shell gets a `beforeLoad` hook for this. A tunable change that makes a scene restart (stress count) simply starts a new recording, so a recording never contains its own reload.
- **Entity-pane edits** are recorded as `{ tick, kind: "edit", entity: <index in world.entities>, path, value }`. Indices are deterministic given the same sim. They're applied through one pure `applyEdit(world, edit)` that both the pane and playback use (including the transform → `prevTransform` snap).
- **Sim-affecting debug commands** declare `sim: true` in their definition. Running one records `{ tick, kind: "command", id }`, and playback runs it at that tick. No such command exists yet. The mechanism is there for Phase 2+ cheats (spawn enemy, kill all). View-only commands (wireframe, stats…) aren't recorded.
- **New architecture rule:** only systems and recorded events mutate the sim. Scene `onTick`/`onFrame`/`onBeforeRender` listeners are view-only. Out-of-band mutations go through `applyEdit`, a recorded tunable, or a `sim: true` command.
- **Input quantization:** `q(v) = round(v × 1024) / 1024` for aim and the move command. Move uses truncation toward zero, so its length stays ≤ 1. The file stores the integers.
- **Input encoding:** a change list. Each record is the ticks since the previous record, then a field mask and only the changed fields: `move` (2 ints), `moveCommand` (null or 2 ints), `aim` (2 ints), `held`/`pressed`/`released` as bitmasks over `ACTIONS` (order fixed in the file header). Idle stretches cost nothing. In memory the recording is packed number arrays, and JSON is built only on save.
- **Hash:** FNV-1a 32-bit. For each entity in `world.entities` order and each component (keys sorted), walk plain data recursively and feed keys, number bits (`Float64` → 2×uint32), booleans, strings and nulls into that component's hash. `Rng` gains `state(): [a, b, c, d]` (read-only, for the checksum).
- **Divergence:** on the first mismatch playback pauses, reports in the pane and `console.warn` (`replay diverged at tick 1834: pawn, transform`), and keeps the ✗ status. Resuming is allowed (it only reports the first divergence). A replay whose scene id doesn't exist fails to load with a clear error. A commit mismatch shows a notice and plays anyway.
- **Playback drives the tick input.** The shell gets a tick input source override. During playback the loop's `update` takes the recorded frame for the current tick instead of `input.sampleTick`, and live input is still sampled and discarded, so no stale presses leak out on take over (plus `input.resetEdges()` at take over). The pane, free camera, picker and Inspector keep working, and entity-pane edits during playback do an implicit take over first.
- **Seeking** reloads (same scene, seed and tick-0 tunables) and fast-forwards in chunks of ~12 ms per frame, with debug draw and rendering off, and a "seeking… 40%" status. Checksums are verified during the fast-forward too. Forward seeks skip the reload.
- **Take over:** the live recording becomes a copy of the replay's header, inputs, events and checksums up to the current tick, with `takenOverAt: <tick>` in the header, then continues recording live.
- **HUD badge during playback only:** a small Preact overlay top-left, `▶ REPLAY 00:42 / 03:10` (red ✗ once diverged), from a `replayStatus` signal. Nothing is shown while merely recording.
- **File header:** `{ format: "stag-replay", v: 1, commit, dirty, recordedAt, scene, seed, tickHz, actions: [...ACTIONS], quant: 1024, ticks, takenOverAt?, tunables: {id: value}, input: [...], events: [...], checksums: [...] }`. The commit comes from a Vite `define` (`git rev-parse --short HEAD` + dirty flag at build/dev start). Loading rejects an unknown `format`/`v` and a different `tickHz`.
- **File names:** `<scene>-<seed>-<YYYYMMDD-HHmmss>.replay.json.gz` for downloads. "Save as test…" names are `[a-z0-9-]+`, and it asks before overwriting.
- **Loading:** a file picker in the pane, plus drag-and-drop of a `.replay.json(.gz)` anywhere on the page (drag-over shows a thin outline). In `pnpm dev` a dropdown lists `src/replay/fixtures/*` via `import.meta.glob` (as URLs).
- **gzip** uses the Web Streams `CompressionStream`/`DecompressionStream`, which exist in both browsers and Node 24, so the same code runs in tests.
- **`window.__game.replay`:** `recording()` (current recording as a replay object), `play(replayOrUrl)`, `seek(tick)`, `takeOver()`, `exit()`, `save()`, `status` (`{ mode, tick, ticks, diverged }`). Commands: `replay.save`, `replay.takeOver`, `replay.exit` (`button: false`).
- **`pnpm replay:update`** = `REPLAY_UPDATE=1 vitest run src/replay`: the fixture test rewrites checksums instead of asserting, and reports which files changed.

## Steps

1. **Pure foundations:** `Rng.state()`, input quantization in `sampleTick`, `replay/checksum.ts`, `replay/format.ts` (change-list encode/decode round-trip), `replay/gzip.ts`. Tests for each.
2. **Scene split:** `SceneSim` + `SceneDef`, `scenes/sims.ts`, split input test and stress into sim and view files. The shell runs `spawn` then `setup`. No behaviour change, so check with restart that the same seed still gives the same layout.
3. **Recorder + player + events (pure):** `recorder.ts`, `player.ts`, `events.ts`, `headless.ts`. Tests: record a scripted session headless, run it back, all checksums match. A deliberately injected `Math.random` into a test system is caught at the right checkpoint with the right component named.
4. **Shell hooks:** `beforeLoad`, tick input source override. Commands get `sim: true`. The entity pane edits through `applyEdit`.
5. **Browser session:** always-on recording, save (download), load (picker + drag-and-drop), playback, tunable snapshot/restore, divergence reporting, take over, seeking, the cap, the Replay pane folder, the badge, `__game.replay`.
6. **Dev saving + fixtures:** Vite middleware + `__COMMIT__`, "Save as test…", fixtures dropdown, `fixtures.test.ts`, `pnpm replay:update`. Record the first fixture (input test: WASD, a few moba clicks, one tunable change, one pane edit).
7. `pnpm check`, `pnpm build`. Verify in agent-browser (below).
8. Docs:
   - AGENTS.md: new rule (only systems and recorded events mutate the sim; `sim: true` commands; view-only scene listeners), scene split, `replay/` layout, `pnpm replay:update`, `__game.replay`

## Implementation notes

- **Verified** in headless Chrome (agent-browser, real WebGPU) on the dev server and the production build (`?debug`), plus in Node (Vitest):
  - A scripted input-test session (WASD, preset switch, click-to-move, a tunable change, a pane edit) replays in sync to the last tick and ends paused on the same pawn position as live play. The recorded `pawn.speed` drives playback, while `stag.debug` keeps the player's own value, which comes back on exit.
  - Seek forward, seek back and step back land on identical states (same positions, no divergence). Take over at tick 100, play on live, save: the combined replay (`takenOverAt: 100`) plays back in sync.
  - A replay with a changed tick-0 tunable reports `✗ at 60: transform`, pauses there, and "jump to last good checkpoint" goes back to 0.
  - Browser recordings saved with "Save as test…" pass headless, and Node-rewritten checkpoints (`pnpm replay:update`) replay in sync in Chrome. Drag-and-drop of a `.replay.json.gz` plays it.
  - Stress scene (500 boxes): seeking to the end of a 2,453-tick replay takes ~170 ms, and back to the middle ~145 ms.
  - Size: a synthetic worst case (aim changing every tick, WASD bursts, clicks) is 526 KB of JSON / **188 KB gzipped for 10 minutes**, ~1.1 MB per hour. The first fixture (210 ticks) is 629 bytes.
  - Production without `?debug` has no `__game` and no badge. Replay code and the fixture endpoints are only in the `devtools` chunk, "Save as test…" is stripped, no fixtures end up in `dist/`, and the player chunk grew ~2 KB gzipped (dmath, quantization, badge).
- **Surprise: `Math.atan2` differs between Chrome and Node.** The first fixture recorded in Chrome diverged headless at tick 88: the pawn's `rotation.y` was `…5401` in the browser and `…5403` in Node. The spec lets `Math.sin/cos/atan2/hypot/pow/exp…` differ per engine and version; only `+ - * /` and `sqrt` are exact. Added **`core/dmath.ts`** (sin, cos, atan, atan2 as fdlibm ports; hypot via `sqrt`) and switched every sim use over. `core/dmath.test.ts` checks accuracy (~1 ulp vs `Math`), `atan2`'s signed-zero/infinity cases, and fails on `Math.random`, transcendental `Math.*` or `**` in sim code (systems, ecs, demo sims, `core/math.ts`). AGENTS.md rule 6 now says so. Firefox ↔ Chrome replays depend on this too.
- **Tweakpane writes shown values back.** The entity pane re-wrote unchanged fields (a spurious `rotation.y` edit got recorded), and the seed field's write-back called `restart()`, which silently ended playback right after it started. Edits that don't change the value are now ignored, and the seed field only restarts for a different seed ("Restart (same seed)" is the button for that). Same guard on "go to tick".
- **Checkpoints also go right before each event tick**, not only every 60 ticks and at the end. An edit made while paused after the last tick would otherwise leave the final checkpoint fingerprinting post-edit state that playback never reaches. Events after the last tick are dropped on save.
- **Loop changes:** `tickCount` now goes up per tick (inside `update` it's the running tick's index), a tick that pauses the loop stops the rest of the frame's ticks, and `canTick` (the replay's end) blocks both `advance` and `step`.
- **Scene split:** `SceneSim` (`scenes/sim.ts`, Babylon-free: `id`, `label`, `systems`, `spawn`) and `SceneDef = SceneSim & { setup }`. `SceneContext` lost `rng` (setup is view-only). Files: `demo/inputTest.ts` + `inputTest.view.ts`, `demo/stress.ts` + `stress.view.ts`, registries `scenes/sims.ts` (headless) and `scenes/index.ts`. The input test's aim ring and overlay now show the sim's (recorded) aim.
- **Replays run with code defaults for tunables they don't mention** (added since), so the player's own tweaks never leak into a replay, in the browser or headless.
- **Tunable tweaks during playback don't take over.** They apply on top of the replay (that's the tuning-comparison use; it may diverge) and also update the player's set-aside values, so they survive exiting. Edits and `sim: true` commands do take over.
- **After a take over** the replay's tunables stay in place until the next load, when the player's come back (restoring mid-run would change the sim under you).
- **Exit replay resumes** live play (the replay paused the loop, not the player).
- **Fixtures are served by dev-server middleware** (`/__replay/list`, `/__replay/fixture`, `/__replay/save`) rather than `import.meta.glob`, so a production build can never bundle them.
- **Badge is top-center**, not top-left: the stats panel lives top-left.
- The file-name timestamp uses UTC (from `recordedAt`).
- **After review:** the Playback folder got a play/pause button under the timeline (⏸ Pause / ▶ Play, and ⟲ Play from start once the replay has ended). The first `input-test-basics` fixture was scripted, and its pane edit teleported the pawn near the end. It was replaced by a 12.5 s hand-played recording (754 ticks, no events), which passed headless as recorded.
