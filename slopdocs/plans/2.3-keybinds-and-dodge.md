# 2.3 Keybinds & Dodge Decision: Implementation Plan

> Status: **built (2026-10-24).** Parent: [implementation-plan.md](../implementation-plan.md) step 2.3.

## Goal

Settle the ability keys for good and decide on dodge. Then build what those decisions need, so that 2.4 (pounce) and 2.5 only have to add ability definitions.

- **No dedicated dodge.** All mobility comes from abilities. A form's arsenal can hold a dodge-like ability (a sidestep, a roll, a blink), but nothing is universal and no key is reserved for one.
- **Q/W/E/R** are the loadout (3 basics + ultimate), as before. **D/F** are two reserved slots (`extra1`/`extra2`) for something outside the loadout (to be decided: items, consumables, relic actives, …).
- **Three cast modes per key, League style:** `Q` quick casts at the cursor, `Shift+Q` normal casts (an indicator, then left click confirms), `Alt+Q` self casts when the ability allows it.

When it's done:

- in the Training yard, the pane's **Test kit** toggle fills Q/W/E/R with four grey-box test abilities. Each one quick casts, normal casts and (where it's flagged) self casts as described below, and hits the dummies.
- a targeted ability on an out-of-range enemy walks the cat into range and casts, like the auto attack's chase.
- the normal cast shows a League-style indicator: the range ring round the cat and the ability's shape at the aim.
- `F` no longer does anything, `D` and `F` are bound to empty slots, and the design doc records the decisions.

Out of scope:

- **real abilities:** pounce is 2.4, the first damage ability 2.5. The test kit is dev-only and never in a player build's loadout.
- **what D/F are for.** The slots exist and are empty.
- **remapping and per-slot cast-mode settings** (16.1). The three modes are the defaults, written as data in the bindings.
- **the indicator's final look** (art/styling phase). Grey-box League style for now.
- **HUD and cooldown display** (2.6), **enemy telegraphs** (3.2).
- **the WASD (`mmo`) preset**, which is dormant: it only loses `dodge`. It gets no D/F and no Shift/Alt chords.

## Decisions

| Area | Decision | Notes |
|---|---|---|
| Dodge | **No dedicated dodge** | "No dedicated dodge, although a character can have a dodge-like ability." Mobility lives in each form's abilities. The `dodge` action and its bindings (`F` in moba, `Space` in mmo) are removed. |
| Extra keys | **D/F reserved for later** | Not part of the form's loadout. |
| Reservation depth | **Actions + empty slots** | Two actions bound to `KeyD`/`KeyF`, two caster slots in the framework, empty like `ability1`–`3` were in 2.2. |
| Names | **`extra1` / `extra2`** | Placeholders, renamed once we know what goes there. |
| Default cast mode | **Quick cast** | The key casts at the cursor the moment it goes down (what 2.2 already does). |
| `Shift`+key | **Normal cast** | Shows the indicator; the cast waits for a confirm. |
| `Alt`+key | **Self cast, when applicable** | Defaults like the others, written in the bindings. |
| Normal cast confirm/cancel | **League's rules** | Left click confirms at the cursor. Right click cancels and is still a normal move or attack order. Another ability key switches to that ability. Esc cancels without opening the pause menu. No cooldown is spent until it's confirmed. |
| Self cast applicability | **Per-ability flag, else quick cast** | `selfCast: true` in the definition. For `point` aims it lands at the caster's feet, for `target` aims it targets the caster. Without the flag `Alt+Q` acts like `Q`, so holding Alt never swallows a press. |
| Scope | **Full mechanics + a dev test kit** | All three modes, the indicator, D/F and the walk-into-range work in 2.3, playable through the test kit. |
| Test kit | **Line, circle, cone + an R, behind a pane toggle** | A recorded sim command (`testKit`), so replays keep it. It fills empty slots only. D/F stay empty. |
| Indicator | **League style, grey-box** | "We'll need to style this as we like later during some art/styling phase, for now, League style is good." |
| Target out of range | **Walk into range, then cast** | League. The cast becomes an order, like the auto attack's chase. |

### Defaults I picked (object if you disagree)

**How the modifiers reach the sim:** as data in the bindings, using the existing chord mechanism. A control can already trigger several actions (`Shift+Mouse2` → `attackMove` + `confirm`), so:

- `Shift+KeyQ` → `ability1` + `normalCast`, `Alt+KeyQ` → `ability1` + `selfCast`, and the same for W/E/R and D/F.
- `normalCast` and `selfCast` are new actions, pressed in the same tick as the slot. The sim reads "slot pressed together with `normalCast`", and the replay records both like any other press.
- Remapping (16.1) can then put any mode on any key without touching the sim.
- `input/state.ts` learns `Alt+` chords next to `Shift+`. `dom.ts` calls `preventDefault` on Alt keydowns while the game has focus, so Firefox doesn't open its menu bar.
- `Shift+Mouse2` (attack move) is unchanged.

**Normal cast state:** `player.aiming: { slot } | null`, in the sim, because a confirm changes the sim.

- **Arming:** `Shift+Q` arms aiming when the slot could start now (ready, no other cast running). Otherwise the press waits in the 0.2 s buffer and arms once it can, like League refusing to enter targeting while on cooldown.
- **Confirm:** left click (`confirm`) queues the cast exactly as a quick cast would at that tick's cursor and hover, then clears aiming.
- **Cancel:** right click, `A` (stop), and Esc each cancel. Pressing another slot's key cancels it too, and that key's own mode applies (`Q` while aiming W quick casts Q, `Shift+Q` switches the aiming to Q). Pressing the same key without Shift while aiming quick casts it.
- **Attack move:** aiming and the attack move are both "armed until a left click", so arming one disarms the other.
- **Esc:** the shell reads `player.aiming` and doesn't open the pause menu while it's set. The sim sees `pause` pressed and clears aiming. The browser still releases pointer lock on Esc (we can't stop that outside fullscreen's keyboard lock), so the cursor unlocks until the next canvas click. If that feels bad, we revisit it.
- **Self-aimed abilities** (`aim: "self"`): there's nothing to aim, so `Shift+key` just casts.

**Quick cast details:** unchanged from 2.2. A press queues the slot with the cursor point and the hovered uid. It has no indicator, and a held key doesn't repeat.

**Walk into range (target aim):** a target cast whose target is out of range is kept as an order instead of expiring after the buffer.

- It works like the auto attack's chase: path toward the target, repath as it moves, cast the moment it's in range.
- A move order, stop, another cast, the attack move, or the target becoming invalid cancels it.
- Point aims keep being pulled in to their range, and direction aims always fire, as in 2.2.
- State is a flag on `caster.queued` (`chase: true`, no expiry while it's set), so `casting` and the AA chase share the pathing code in `playerControl`.

**The test kit** (`data/testKit.ts`, tunables group `testKit`, debug pane button "Test kit" in Gameplay). The numbers are starting points:

| Slot | Ability | Aim | Shape | Windup | Cooldown | Damage | Self cast |
|---|---|---|---|---|---|---|---|
| Q | Test line | direction | line 8 m × 1 m | 0.25 s | 4 s | 60 | no |
| W | Test burst | point, range 7 m | circle r 2 m at the point | 0.4 s | 6 s | 80 | **yes** (at your feet) |
| E | Test cone | direction | cone 3.5 m, 45° half-angle | 0.15 s | 3 s | 40 | no |
| R | Test strike | **target**, range 6 m | single target | 0.5 s | 10 s | 150 | no |

- **R is a targeted strike** rather than a second big circle, so that walking into range has something to test. It still covers "the ultimate slot".
- All four root during the windup and face the aim.
- Their only VFX is a short grey-box flash of the area where the effects land (overlay scene, ~0.25 s), plus the existing hit fx on dummies.

**The indicator** (`render/aimIndicator.ts`, overlay scene, pale blue/white, flat):

- the range ring round the cat (`render/rangeRing.ts`, reused from the attack move) for `target` and `point` aims, and the length of the line or cone for `direction` aims
- the shape where it would land: the line's rectangle and the cone from the cat toward the cursor, the circle at the cursor clamped to range, and for `target` the hovered enemy outlined with the attack cursor
- the cursor turns into the attack cursor while aiming, as it does for the attack move

**Bindings after 2.3 (moba):**

| Control | Action |
|---|---|
| Right click | move / attack order (`primary`) |
| Left click | `confirm` (normal cast, attack move) / `interact` |
| Q W E R | `ability1`–`3`, `ultimate` (quick cast) |
| Shift + Q W E R D F | normal cast |
| Alt + Q W E R D F | self cast |
| D F | `extra1`, `extra2` (empty) |
| A | stop |
| S, Shift + right click | attack move |
| Space | center camera (held: follow) |
| Esc | cancel aiming, else the pause menu |

**Tidy-up:** the stale `switchControls` action (the `M` key went in 2.2) is removed with `dodge`. Replay files store action names, not indices, so the old fixtures keep decoding (unknown names are skipped).

## Architecture

```
input/actions.ts       − dodge, − switchControls; + extra1, extra2, normalCast, selfCast
input/bindings.ts      moba: D/F, Shift+/Alt+ chords for the six slot keys; mmo: − dodge
input/state.ts         Alt+ chords next to Shift+
input/dom.ts           preventDefault on Alt while focused
ecs/world.ts           SLOTS + extra1, extra2; player.aiming; QueuedCast.chase
data/abilities.ts      AbilityDef.selfCast
data/testKit.ts        the four test abilities + `testKit` tunables (Babylon-free)
systems/playerControl  cast modes: quick / arm aiming / confirm / cancel / self cast; walk into range
systems/casting.ts     queued.chase never expires; self-cast aim resolution
systems/cheats.ts      testKit sim command (fills empty slots)
combat/abilities.ts    resolveAim for self casts (point → caster position, target → caster uid)
render/aimIndicator.ts the normal-cast indicator (overlay)
render/testKitFx.ts    the area flash when a test ability lands
shell.ts               Esc: no pause menu while player.aiming
```

All of it except `render/`, `dom.ts` and `shell.ts` stays Babylon-free and deterministic.

## Implementation notes

- **Built in parallel.** A small commit first fixed the shared contract (the new actions, the `extra1`/`extra2` slots, `player.aiming`, `queued.chase`, `selfCast`). Four agents then built input, sim, test kit and view, each in its own git worktree, and were merged one by one. The only conflict was a few lines in `shell.ts`.
- **New state is optional** (`player.aiming`, `player.aimQueued`, `queued.chase`, `testKit`), absent when unused, so the existing replay fixtures passed unchanged.
- **Aiming during a cast (changed from the plan):** arming checks only that the slot has an ability and is off cooldown, not that no other cast is running. The auto attack's windup (≈0.26 s) is longer than the 0.2 s buffer, so `Shift+Q` during an auto would have been dropped. Aiming is only UI (League lets you target during an auto), and the confirm queues the cast, which starts once the running one is over.
- **A buffered arm** (`Shift+Q` while on cooldown) lives in `player.aimQueued` (`{ slot, age }`) for `abilities.buffer`, and arms the first tick the slot is ready.
- **Self cast** is a queued cast whose target is the caster's own uid. `resolveAim` honours it only for abilities with `selfCast` (a `point` aim lands on the caster, a `target` aim targets it). `enemyOf` is unchanged. Side effect: a quick cast with the cursor on your own body self casts a `selfCast` ability, as in League.
- **Cancels:**
  - **Aiming** is cancelled by:
    - a fresh right click (it still gives its move or attack order). One still held from before doesn't cancel.
    - `A`
    - `S`, checked before the confirm, so S and a left click in the same tick go to the attack move
    - Esc. The sim clears the aim, and the shell doesn't open the menu while aiming.
    - another slot key with an ability, which then casts in its own mode
  - Pressing an empty slot's key (`D`/`F`) cancels nothing.
  - **A walk into range** is dropped by:
    - a right click
    - `A`
    - any slot press
    - an issued attack move (the click, not the `S` arm)
    - the target no longer being an enemy
  - Dropping it also drops the path, so the cat stops. The auto attack's target and chase are left alone.
- **Modifiers in the input layer:** precedence is a bound `Alt+` chord, then a bound `Shift+` chord, then the plain control. A modifier key counts as bound only when the preset has a chord with it, so Alt does nothing in `mmo`. While Alt is held, `dom.ts` lets through only Alt itself and bound `Alt+` chords: other Alt shortcuts (Alt + arrows) stay the browser's. Alt's keydown and keyup are cancelled, so Firefox doesn't open its menu bar. `MOBA_SLOT_KEYS` in `bindings.ts` is the one table the slot keys and their chords are built from.
- **The test kit** marks the player with `testKit: SlotId[]`, the slots it filled, so turning it off empties exactly those (and drops an aim on one of them). `data/testKit.ts` registers its abilities when it's imported, and `systems/cheats.ts` imports it, so headless replays know them. The pane toggle is in Gameplay next to noclip.
- **The indicator** places the ring as `resolveAim` measures: the movement radius + range for `target`, range from the center for `point`, the longest area for `direction`. The areas follow the live cursor every frame. During a replay that's your mouse, not the recorded aim.
- **The cast flash** (`render/castFx.ts`) runs for every caster and any slot but the auto attack. It flashes where the sim applied the area: at the end of the windup, or on each channel pulse. An instant cast (windup 0) starts and lands within one tick, so it gets no flash yet. The test kit has none.
- **Not done yet (for 2.4/2.5):** single-target damage (`area: null`) has no hostility check, so a self-castable targeted ability with damage would hit its caster.
- `cf` bumped from 1.0.0-beta.18 to 1.0.0-beta.21.
- **Screenshots on WSL:** agent-browser's own Chrome needed `install --with-deps`, and even then headless WebGPU didn't render in WSL (SwiftShader lost the device; WSL's Vulkan gave a white canvas at 2 fps). We switched WSL to mirrored networking, and agent-browser drives a headless Windows Chrome over a localhost-only CDP port (procedure in `devlog/README.md`). Binding the debug port to 0.0.0.0 was refused by the agent's safety check, rightly. Mirrored ports have one trap: a Windows TIME_WAIT on 5746 (from polling it while nothing listened) blocked `pnpm dev` until it expired.
- **Browser check (Windows Chrome, real GPU):** each indicator (W circle + 7 m ring, Q rectangle, E cone), the W landing flash with 80 damage, a right-click cancelling a Q aim (no cast, the cat moves), Esc cancelling an E aim with no menu (and Esc still pausing otherwise), Alt+W at the cat's feet with the cursor elsewhere, and R on a dummy 11 m away walking into range and striking.

## Follow-up: the kit always on, and an ability bar (2026-10-25)

Asked for after the first playtest: "Remove the debug pane test kit option, just have this always on for now. We need some kind of UI to show the abilities and their cooldowns, and their keybinds, and their icons [...] Just something minimal for now."

- **The test kit is the Cat's Q/W/E/R from spawn** (`scenes/arena.ts` merges `TEST_KIT_SLOTS` under `CAT_SLOTS`), in player builds too, until real abilities replace it slot by slot. The `cheats.testKit` command, its pane toggle and the `testKit` marker are gone.
- **Fixtures:** `yard-cast-modes` ran the command at tick 0, which is the same as spawning with the kit, so that event was dropped from the file. Every fixture's transforms, health and casts were compared every 10 ticks against the previous commit (identical in all ten), then `pnpm replay:update` rewrote the checksums (the player has four more slots).
- **The ability bar** (`ui/AbilityBar.tsx`) sits at the bottom center: the auto attack, then Q/W/E/R, then the empty D/F. Each slot has its icon, its key from the current bindings (`controlLabel` in `input/bindings.ts`), a dark sweep and seconds while it cools down, and an outline while it's being aimed. `src/hud.ts` builds the slots from the world for the shell once a frame and writes the `abilityBar` signal only when what it shows changes (cooldowns to 0.1 s). Icons are placeholder line drawings picked by a new `icon` id in the ability data (`ui/abilityIcons.tsx`).
- It's a stand-in for 2.6's HUD, which reworks it.
- **A cast bar**, asked for in the same playtest ("my char has some amount of time where they can't move while casting it [...] we need to show a cast bar on screen, same as league"): `ui/CastBar.tsx`, just above the ability bar, with the ability's name. It fills during a windup and drains during a channel. Auto attacks and instant casts never show one, as in League. `hud.ts` publishes `castBar` from `caster.cast` and the ability's stats, rounded to 1 %, so it only writes while something is being cast.
- **"Pounce isn't moving me":** there's no pounce yet. `R` is the test kit's targeted strike, which walks into range but doesn't move you itself. Pounce is 2.4.
